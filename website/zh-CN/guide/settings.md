# 设置

VMark 的设置面板让你可以自定义编辑器的方方面面。使用 `Mod + ,` 或通过菜单栏中的 **VMark > 设置** 打开。

设置窗口的侧边栏按字母顺序（依英文名称）列出各章节，"关于"在底部，"高级"显示时位于其下方。更改立即生效——没有保存按钮。

使用侧边栏顶部的 **搜索框**，可按名称或描述在所有面板中筛选设置——匹配的行会集中显示，你无需知道某个设置位于哪个类别。要将所有设置恢复为出厂默认值，请使用"关于"部分中的 **恢复默认值**。

## 外观

控制视觉主题和窗口行为。

### 主题

从六种颜色主题中选择。活动主题以其色块周围的圆环标示。

| 主题 | 背景色 | 风格 |
|------|--------|------|
| White | `#FFFFFF` | 纯净白色，对比度最高 |
| Paper | `#EEEDED` | 温暖的新闻纸色（默认） |
| Mint | `#CCE6D0` | 柔和绿色，护眼 |
| Sepia | `#F9F0DB` | 书页纸色，适合长时间阅读 |
| Night | `#23262B` | 深石板色，适合弱光环境 |
| Solarized | `#002B36` | Solarized Dark，经典配色 |

::: info Windows 10 和 Linux 仅提供 White 与 Night
在 Windows 10 和 Linux 上，标题栏由系统绘制，而系统只能呈现浅色或深色。因此这两个平台只提供 **White** 和 **Night**，无法与系统窗口边框匹配的主题会显示为二者中较接近的一个：Paper、Mint 和 Sepia 显示为 White，Solarized 显示为 Night。你保存的选择不会被更改——在 macOS 和 Windows 11 上可以使用全部主题。在 Windows 11 上，标题栏会采用主题本身的颜色；菜单栏仍以浅色或深色绘制。
:::

#### 跟随系统外观

| 设置 | 描述 | 默认值 |
|------|------|--------|
| 跟随系统外观 | 随系统自动在浅色与深色主题之间切换 | 关闭 |

启用后，单一的主题行会被两行取代——**浅色主题**（系统处于浅色模式时使用，默认 Paper）和 **深色主题**（深色模式时使用，默认 Night）。系统外观一变化，VMark 立即在两者之间切换；你手动选择的主题会被保留，并在关闭此选项时恢复。

### 侧边栏

| 设置 | 描述 | 默认值 | 选项 |
|------|------|--------|------|
| 侧边栏样式 | 侧边栏与工作区栏的外框样式。**全高**像 macOS 自带的侧边栏一样贴合窗口边缘，并以细分隔线与编辑区分开；**卡片**以圆角和阴影悬浮于窗口内。同样适用于设置窗口 | 全高 | 全高、卡片 |

### 窗口

| 设置 | 描述 | 默认值 |
|------|------|--------|
| 在标题栏显示文件名 | 在 macOS 窗口标题栏显示当前文件名。**仅 macOS**——其他平台隐藏此设置，因为 Windows 和 Linux 始终在系统标题栏中显示文件名 | 关闭 |

在 macOS 上，VMark 在系统标题栏之上绘制自己的标题栏，因此文件名是该标题条中的可选元素。在 Windows 和 Linux 上，系统会在窗口上方绘制真正的标题栏：文件名（有未保存的更改时带 `•`）始终显示在那里，VMark 不会再添加自己的标题条。

### 专注模式

| 设置 | 描述 | 默认值 | 选项 |
|------|------|--------|------|
| 暗化程度 | 专注模式下非聚焦内容的暗化强度。**标准** 保留默认的仅颜色暗化；**强** 和 **更强** 在此基础上逐级降低不透明度 | 标准 | 标准、强、更强 |

## 编辑器

排版、显示、编辑行为、空白字符和大文件设置。

### 排版

| 设置 | 描述 | 默认值 | 选项 |
|------|------|--------|------|
| 拉丁字体 | 拉丁文（英文）字体族 | 系统默认 | 系统默认、Athelas、Palatino、Georgia、Charter、Literata——以及任何已安装的字体 |
| 中日韩字体 | 中文、日文、韩文字体族 | 系统默认 | 系统默认、PingFang SC、Songti SC、Kaiti SC、Noto Serif CJK、Source Han Sans——以及任何已安装的字体 |
| 等宽字体 | 代码和等宽文本的字体族——集成终端也使用此字体 | 系统默认 | 系统默认、SF Mono、Monaco、Menlo、Consolas、DejaVu Sans Mono、Liberation Mono、Ubuntu Mono、Noto Sans Mono、Noto Sans Mono CJK SC、JetBrains Mono、Fira Code、SauceCodePro NFM、IBM Plex Mono、Hack、Inconsolata——以及任何已安装的字体 |
| 字号 | 编辑器内容的基础字号 | 18px | 14px、16px、18px、20px、22px |
| 行高 | 行间垂直间距 | 1.8（宽松） | 1.4（紧凑）、1.6（正常）、1.8（宽松）、2.0（宽敞）、2.2（超宽） |
| 块间距 | 块级元素（标题、段落、列表）之间的视觉间距，以行高的倍数计算 | 1x（正常） | 0.5x（紧凑）、1x（正常）、1.5x（宽松）、2x（宽敞） |
| 中日韩字符间距 | 中日韩字符之间的额外间距，以 em 为单位 | 关闭 | 关闭、0.02em（微妙）、0.03em（轻微）、0.05em（正常）、0.08em（宽）、0.10em（更宽）、0.12em（超宽） |

#### 使用你自己安装的字体

上面列出的名称只是精选列表，而不是全部。三个字体选择器都带有一个 **已安装字体** 分区，列出本机上的所有字体族，因此你安装的字体——霞鹜文楷、Iosevka、思源宋体——与内置字体的选择方式完全相同。

在列表末尾选择 **自定义…** 即可改为输入字体族名称。请使用系统报告的准确名称（macOS：字体册；Windows：设置 → 个性化 → 字体）——霞鹜文楷（LXGW WenKai）的名称是 `LXGW WenKai`。名称输入完整后字体立即生效；如果没有任何变化，说明该名称与已安装的字体族不匹配。包含引号、逗号、分号或括号的名称会被拒绝，该行会给出提示。

::: tip 已安装字体仅限 macOS
macOS 会为你列出所有已安装的字体族。在 Windows 和 Linux 上该分区为空，需通过 **自定义…** 输入——输入字体族名称的方式在三个平台上完全相同。
:::

所选字体会沿用到 PDF 导出中，因为 PDF 导出使用同一引擎和同样的字体进行渲染。HTML 导出无法打包你机器上的字体，因此导出的页面会回退到读者自己的字体，除非对方也安装了相同的字体族。

### 显示

| 设置 | 描述 | 默认值 | 选项 |
|------|------|--------|------|
| 编辑器宽度 | 最大内容宽度。较大的值适合大显示器；较小的值提高可读性 | 50em（中等） | 36em（紧凑）、42em（窄）、50em（中等）、60em（宽）、80em（超宽）、无限制 |

::: tip 同样的宽度，拉丁文与中日韩文字读起来不同
编辑器宽度以 `em` 为单位，因此每行能容纳的*字符*数取决于文字系统：在 50em 下，一行拉丁文约容纳 90–100 个字符（约为排版师所推荐的 45–75 字符行长的 2 倍，适合双栏编辑器），而一行中日韩文字约容纳 50 个全角字符——正好落在中文传统的 40–60 字范围内。如果你主要写拉丁文正文并希望获得书籍般的行长，请选择 36–42em；对于以中日韩文字为主的文档，默认值已经是经典行长。
:::

::: tip
18px 字号下的 50em 约为 900px——对大多数显示器来说是舒适的阅读宽度。
:::

|------|------|--------|------|
| 启用 Markdown 检查 | 检查常见 Markdown 问题（损坏的链接、缺少 alt 文本、标题层级跳跃、未关闭的代码围栏等） | 开启 | 开启/关闭 |

### HTML 渲染

| 设置 | 描述 | 默认值 | 选项 |
|------|------|--------|------|
| 富文本中的原始 HTML | 控制是否在所见即所得模式下渲染原始 HTML 块 | 已清理 | 隐藏、已清理、已清理 + 样式 |
| 允许的 HTML 标签 | 渲染的标签集合范围 | 严格 | 严格、扩展 |
| 额外允许这些标签 | 额外允许的标签名，以逗号分隔 | _（空）_ | 例如 `kbd, samp, var` |

::: tip
**隐藏** 会折叠原始 HTML，不渲染任何内容。**已清理** 在去除危险标签后渲染 HTML。**已清理 + 样式** 额外保留内联 `style` 属性中的安全子集。

**严格** 只允许一小组保守的标签。**扩展** 额外渲染 `<svg>`（及其安全的子元素）、`<figure>`/`<figcaption>`、`<details>`/`<summary>` 以及其他语义/结构标签——这些同样都会经过清理。使用 **额外允许这些标签** 可以在此基础上添加特定标签（例如 `kbd, samp, var`）。
:::

::: warning
无论这些设置如何，危险标签（`<script>`、`<style>`、`<iframe>`、`<form>`、事件处理器等）**始终**会被去除——自定义标签字段无法重新启用它们。允许列表的范围只影响所见即所得预览；文件中的原始 HTML 永远不会被修改。
:::

## 文件与图片

文件浏览器、保存、文档历史、图片处理和文档工具。

### 工作区

| 设置 | 描述 | 默认值 |
|------|------|--------|
| 工作区侧栏 | 显示左侧工作区侧栏，并将多个工作区和零散文件保留在同一窗口中 | 关闭 |

侧栏带来的功能请参阅[工作区导轨](/zh-CN/guide/workspace-rail)。

### 文件浏览器

前两项设置仅在打开工作区（文件夹）时有效，并按工作区分别保存。

| 设置 | 描述 | 默认值 |
|------|------|--------|
| 显示隐藏文件 | 在文件浏览器侧边栏中显示点文件和隐藏系统项 | 关闭 |
| 显示所有文件 | 在文件浏览器中显示非 Markdown 文件，非 Markdown 文件会用系统默认应用打开 | 关闭 |
| 显示文件扩展名 | 在侧边栏、标签栏和标题栏中显示完整文件名——显示 `notes.md` 而非 `notes`。无论是否打开工作区都适用 | 开启 |

关闭 **显示文件扩展名** 只会隐藏 VMark 能识别的扩展名。VMark 无法打开的文件无论如何都保留后缀，因此你看到的名称总是磁盘上真实存在的。

### 退出行为

| 设置 | 描述 | 默认值 |
|------|------|--------|
| 确认退出 | 需要按两次 `Cmd+Q`（或 `Ctrl+Q`）才能退出，防止意外退出 | 开启 |
| 关闭时最小化到托盘 | **仅 Windows。** 关闭最后一个窗口时，VMark 继续在系统托盘中运行，而不是退出 | 关闭 |

**关闭时最小化到托盘** 只改变*最后一个*窗口的行为。打开多个窗口时，关闭其中一个仍会关闭它；只有最后一次关闭——原本会退出 VMark 的那一次——现在会把它停放到托盘中。没有任何内容被关闭，因此未保存的工作会原样保留。

- **左键单击** 托盘图标可恢复 VMark。
- **右键单击** 可选择 **显示 VMark** 和 **退出 VMark**。从托盘退出时会先恢复窗口，因此任何未保存更改的提示都会出现在你可以回应的地方。
- `Ctrl+Q` 仍照常退出。
- 在 VMark 位于托盘中时关闭此设置，会在图标消失前恢复窗口，因此绝不会让 VMark 在没有窗口也没有图标的情况下运行。

此设置不会出现在 macOS 或 Linux 上。

## 集成

MCP 服务器和 AI 提供商配置。

### MCP 服务器

MCP（模型上下文协议）服务器允许外部 AI 助手（如 Claude Code 和 Cursor）以编程方式控制 VMark。

| 设置 | 描述 | 默认值 |
|------|------|--------|
| 启用 MCP 服务器 | 启动或停止 MCP 服务器。运行时，状态徽章显示端口和已连接的客户端 | 开启（切换） |
| 启动时启动 | VMark 打开时自动启动 MCP 服务器 | 开启 |
| 自动批准保存到新位置和精灵结果 | 允许 MCP 客户端无需询问即可将文档保存到新位置，并允许精灵直接应用其结果而不显示预览。关闭时，MCP 保存到新路径的请求会被拒绝，并以提示通知你。MCP 对文档的写入从不受此设置限制——每次写入都会记入智能体编辑历史，可从状态栏的 MCP 写入历史中恢复 | 关闭 |

服务器运行时，面板还会显示：
- **端口**——自动分配；AI 客户端通过配置文件发现端口
- **版本**——MCP 服务器附属程序版本
- **工具/资源**——可用的 MCP 工具和资源数量
- **已连接的客户端**——当前连接的 AI 客户端数量

在 MCP 服务器部分下方，你可以一键将 VMark 的 MCP 配置安装到支持的 AI 客户端（Claude Desktop、Claude Code、Codex CLI、Gemini CLI）。

完整详情请参阅 [MCP 设置](/zh-CN/guide/mcp-setup) 和 [MCP 工具参考](/zh-CN/guide/mcp-tools)。

### AI 提供商

配置驱动 [AI 精灵](/zh-CN/guide/ai-genies)的 AI 提供商。同一时间只能激活一个提供商。

**CLI 提供商**——使用本地安装的 AI CLI 工具（Claude、Codex、Gemini）。点击 **检测** 扫描 `$PATH` 中可用的 CLI。CLI 提供商使用你的订阅计划，无需 API 密钥。

**REST API 提供商**——直接连接 API：Anthropic、OpenAI、**OpenAI 兼容**服务（DeepSeek、Groq、OpenRouter……）、Google AI，或本地的 Ollama 服务器（Ollama API）。每个都需要模型名称和 API 密钥——但 Ollama 的密钥是可选的。除 Google AI 外都还需要端点，有标准端点的提供商已预先填好（OpenAI 兼容槽位没有标准端点，需要你自行填写）。

各提供商的详细设置说明请参阅 [AI 提供商](/zh-CN/guide/ai-providers)。

有可用更新时，会显示一张卡片，显示新版本号、发布日期和版本说明。你可以 **下载** 更新、**跳过** 此版本，或——下载完成后——**重启以更新**。

#### 更新与你安装 VMark 的方式一致

更新程序下载的是与你安装时相同的包格式，而不是每个平台固定一种：

| 你安装的是 | 更新程序获取的是 |
|---|---|
| macOS `.dmg` | 已签名的应用包 |
| Windows `.exe`（NSIS） | `.exe` 安装程序 |
| Windows `.msi` | `.msi` 安装包 |
| Linux `.deb` | `.deb` 软件包 |
| Linux `.rpm` | `.rpm` 软件包 |
| Linux AppImage | AppImage |

在 Linux 上，更新 `.deb` 或 `.rpm` 安装会调用系统包管理器，因此会提示你进行身份验证——安装系统软件包需要 root 权限。AppImage 更新会原地替换文件，无需提示。

#### 如果更新卡住

检查和下载都要经过网络，而一个挂起而非直接失败的连接可能会让更新永远处于进行中。如果检查一分钟没有进展，或者下载或安装三分钟没有进展，VMark 会在文档窗口中显示一条常驻的 **更新已停滞** 通知。其 **重试** 按钮会让更新程序回到空闲状态，以便你再次尝试——本部分中的 **立即检查** 或下一次自动检查，都会重新开始一次全新的检查。

更新活动会写入日志文件，因此如果问题反复出现，值得将日志附在错误报告中：

| 平台 | 日志位置 |
|---|---|
| macOS | `~/Library/Logs/app.vmark/` |
| Windows | `%LOCALAPPDATA%\app.vmark\logs\` |
| Linux | `~/.local/share/app.vmark/logs/` |

### 重置

| 设置 | 描述 |
|------|------|
| 恢复默认值 | 将这些面板中的设置恢复为默认值。会先出现确认提示——此操作无法撤销 |

有三类内容单独存储，**不会**被重置：键盘快捷键自定义（请在[快捷键](#快捷键)面板中使用 **全部重置**）、你的 AI 提供商配置，以及按工作区保存的文件浏览器设置（**显示隐藏文件**、**显示所有文件**）。界面语言会恢复为系统语言。

开发者和系统级配置。

### 链接协议

| 设置 | 描述 | 默认值 |
|------|------|--------|
| 自定义链接协议 | VMark 视为链接的额外 URL 协议，以标签形式输入每个协议 | `obsidian`、`vscode`、`dict`、`x-dictionary` |

这个列表有两个作用。插入链接时，剪贴板中使用这些协议的 URL 会像 `https://` 一样被识别为链接。打开链接时，只有协议为 `http`、`https`、`mailto` 或在此列表中的链接，VMark 才会交给系统打开——因此 `obsidian://open?vault=...` 和 `vscode://file/...` 链接会在对应的应用中打开，其他协议则被拒绝。少数协议无论列表如何都不能被启用：`javascript:`、`data:`、`file:` 等。

你删除的默认协议会保持删除状态。之后的 VMark 版本新增的默认协议，会在该版本首次启动时加入你的列表，且只加入一次。

| 同时保持两个编辑器活跃 | 同时挂载所见即所得和源码模式编辑器，以加快模式切换，会增加内存使用 | 关闭 |

### 一致性

| 设置 | 描述 | 默认值 | 选项 |

| 语义检查置信度 | 检查的答案被记录为判定之前所需的把握程度。低于该值时，答案仍会保留，但被标记为未知 | 0.9 | 0.7、0.8、0.9、0.95 |

### 工作流文件

| 设置 | 描述 | 默认值 | 选项 |
|------|------|--------|------|
| 获取 Action 元数据 | 允许 VMark 从引用的 GitHub Actions 获取 `action.yml`，以填充结构化编辑器中的 `with:` 表单。关闭后，工作流编辑器完全离线 | 开启 | 开启/关闭 |

### 工作流

GitHub Actions 查看器没有开关：打开 `.github/workflows/` 下的文件就会显示图和表单编辑器，源码窗格的辅助功能（表达式补全、光标与画布同步、`uses:` 跳转到定义）也会随之加载。这里保留的是查看器唯一的一项偏好设置，以及独立的执行引擎。

| 设置 | 描述 | 默认值 | 选项 |
|------|------|--------|------|
| 保存时保留 YAML 格式 | 通过表单面板保存工作流编辑时，借助 CST 往返管线保留原 YAML 的注释、锚点、键序和空行。关闭时使用紧凑序列化器（更快但有损） | 开启 | 开启/关闭 |
| 工作流引擎 | 运行 VMark 自己的 YAML 工作流文件：工作流文件打开时，源码旁会显示它的步骤图和运行 / 取消工具栏，工作流精灵也可以执行。步骤可能调用 AI 提供商并写入文件，因此在你主动开启之前保持关闭 | 关闭 | 开启/关闭 |

引擎不会改变查看器显示的内容：无论引擎是否开启，GitHub Actions 文件都会在查看器中打开；引擎关闭时，VMark 工作流文件显示为普通的 YAML 树。引擎关闭时，VMark 还会直接拒绝工作流执行请求，而不只是隐藏按钮——包括通过 MCP 发来的请求——并报告“工作流引擎已在设置中关闭”。

这两行都位于 **开发者工具** 之下（见下文）——开启开发者工具即可显示它们。查看器请参阅 [Workflow 查看器](/zh-CN/guide/workflow-viewer)，引擎请参阅 [Genie 工作流](/zh-CN/guide/workflows)。

### 内嵌浏览器

| 设置 | 描述 | 默认值 | 选项 |
|------|------|--------|------|
| 内嵌浏览器 | 应用内网页浏览器（仅 macOS）。开启时，**新建浏览器标签页** 会出现在文件菜单和命令面板中，MCP `browser` 工具也可用。关闭它会关闭已打开的浏览器标签页，并撤下 AI 自动化功能 | 开启 | 开启/关闭 |
| AI 浏览器会话 | 选择 `沙盒`（推荐，隔离且不持久保存的 AI Cookie）或 `共享配置文件`（使用你本人的浏览配置，访问目标需经批准） | 沙盒 | 沙盒 / 共享 |
| 允许 AI 回环访问 | 允许 AI 导航到 localhost 和回环地址。私有局域网、元数据和链路本地地址范围仍被阻止 | 关闭 | 开启/关闭 |

这些设置位于 **高级 → macOS** 下，且只在 macOS 上显示。两个 AI 安全策略行只在浏览器开关开启时显示，并且不受该开关开启的影响——在你更改之前，它们会一直保持沙盒 / 阻止回环。完整功能介绍请参阅[内置浏览器](/zh-CN/guide/browser)。

### 平台特定

| 设置 | 描述 | 默认值 | 平台 |
|------|------|--------|------|
| 打开时清除 macOS 隔离属性 | 打开工作区时，从工作区文件夹及其中直接包含的、VMark 能打开的文件上移除 macOS 下载隔离属性（`com.apple.quarantine`）（不处理子文件夹）。否则在 VMark 运行时，macOS 可能会悄无声息地忽略你在访达中双击已下载文件的操作。界面中显示为 **高级 → macOS** 下的 **打开工作区时清除下载隔离标记** | 开启 | macOS |

### 开发者工具

**开发者工具** 是一个会持久保存的总开关，用于实验性和仅供开发的设置。开启后会显示 **保存时保留 YAML 格式** 行、**工作流引擎** 开关以及 **热退出开发工具** 面板（用于测试会话捕获、检查、恢复、清除和重启的按钮）。由于该开关会被保存，你启用的开发中功能在各次会话之间以及正式版本中都能保持可用——无需每次打开设置时都重新启用开发者工具。

它还会在设置之外显示[知识库](/zh-CN/guide/knowledge-base)：**视图 → 切换知识库** 菜单项、命令面板命令和 `Ctrl + Shift + 4` 快捷键在开发者工具开启前都是隐藏的，因为目前任何平台的正式版本都没有附带该功能所需的内容服务器运行时。

| 设置 | 描述 | 默认值 |
|------|------|--------|
| 开发者工具 | 启用开发者模式，并显示下列实验性和仅供开发的设置 | 关闭 |
