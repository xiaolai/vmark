# 工作流精灵

**工作流精灵**是保存在精灵目录中的 [精灵工作流](/zh-CN/guide/workflows)——一个多步骤的 YAML 流水线——文件扩展名为 `.yml` 或 `.yaml`。它会像 Markdown 精灵一样出现在精灵选择器（`Mod + Y`）和**编辑 → Genies** 中；选中它会通过工作流引擎运行整个流水线，而不是发送单个提示词。

## 前提条件

| 前提条件 | 原因 |
|----------|------|
| 打开**设置 → 高级 → 开发者工具**，再开启**工作流引擎** | 引擎默认关闭。引擎关闭时，选择器仍会列出工作流精灵，但运行时会失败并提示“工作流引擎已在设置中关闭” |
| 已打开一个工作区 | `action/save-file` 等动作步骤会相对于工作区根目录解析路径；没有工作区时，VMark 会显示一条提示，且不会开始运行 |
| 已配置 [AI 服务商](/zh-CN/guide/ai-providers) | 精灵步骤调用当前激活的服务商，与 Markdown 精灵使用的相同 |

## 编写工作流精灵

将 YAML 文件放在精灵目录（**编辑 → Genies → 打开 Genies 文件夹**）下的任意位置；与 Markdown 精灵一样，子文件夹会成为分类。选择器以文件名作为精灵名称，并以 YAML 的 `description`（若没有，则用其 `name`）作为第二行。工作流精灵的作用范围是整个文档——运行时没有可处理的选区——因此每个步骤都要提供自己的 `with: { input: … }`，它所调用的 Markdown 精灵会把该值原样绑定到各自的 `{{content}}` 占位符。

内置的 `triage-and-translate.yml` 示例是现成的起点：把它复制到该目录，然后替换其中的种子文本。它的存放位置、完整的 YAML 结构、表达式、审批、每步模型与超时都记录在 [精灵工作流](/zh-CN/guide/workflows) 中；工作流精灵的运行会照常执行，审批对话框也照常弹出，但它不显示实时步骤图，不能从工作流面板取消（运行期间，面板上的“运行”会提示引擎正忙），面板也不为它提供“恢复文件”。

另请参阅 [AI 精灵](/zh-CN/guide/ai-genies)，了解单提示词的 Markdown 精灵格式。
