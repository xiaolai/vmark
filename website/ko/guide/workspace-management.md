# 워크스페이스 관리

VMark에서 워크스페이스는 프로젝트의 루트로 열린 폴더입니다. 워크스페이스를 열면 사이드바에 파일 트리가 표시되고, 빠른 열기가 파일 트리에 표시되는 모든 파일을 찾을 수 있고, 터미널이 프로젝트 루트에서 시작하고, 열린 탭이 다음 번을 위해 기억됩니다.

워크스페이스 없이도 개별 파일을 열 수 있지만 파일 탐색기, 프로젝트 내 검색, 세션 복원을 사용할 수 없습니다.

::: tip 한 창에서 여러 워크스페이스 사용
실험적 기능인 [워크스페이스 레일](/ko/guide/workspace-rail)을 사용하면 하나의 창에 여러 워크스페이스를 담아 두고 전환할 수 있습니다 — 각 워크스페이스는 자체 탭, 파일 트리, 레이아웃을 가집니다.
:::

## 워크스페이스 열기

| 방법 | 방법 |
|------|------|
| 메뉴 | **파일 > 워크스페이스 열기** |
| 빠른 열기 | `Mod + O`, 그런 다음 하단의 **찾아보기...** 선택 |
| 드래그 앤 드롭 | Finder에서 마크다운 파일을 창으로 드래그 — VMark가 프로젝트 루트를 감지하고 자동으로 워크스페이스를 엽니다 |
| 최근 워크스페이스 | **파일 > 최근 워크스페이스** 에서 이전 프로젝트 선택 |

워크스페이스를 열면 VMark가 파일 탐색기와 함께 사이드바를 표시합니다. 워크스페이스가 이전에 열렸다면 이전에 열려 있던 탭이 복원됩니다.

Windows와 Linux에서는 명령줄로 넘긴 폴더(`vmark C:\notes` 또는 `vmark ~/notes`)가 macOS에서 Dock 아이콘에 폴더를 끌어다 놓을 때처럼 자체 창에서 워크스페이스로 열립니다. VMark가 이미 실행 중일 때도 마찬가지입니다.

::: tip
현재 창에 저장되지 않은 변경 사항이 있는 경우 VMark는 작업을 대체하는 대신 새 창에서 워크스페이스를 열도록 제안합니다.
:::

## 파일 탐색기

파일 탐색기는 워크스페이스가 열려 있을 때마다 사이드바에 나타납니다. 워크스페이스 폴더를 루트로 하는 마크다운 파일 트리를 표시합니다.

### 탐색

- 폴더를 **단일 클릭** 하여 확장하거나 축소합니다
- 파일을 **단일 클릭** 하여 탭에서 엽니다
- 선택한 항목에서 **Enter** (또는 `F2`)를 누르면 인라인으로 이름 변경을 시작합니다
- VMark가 직접 편집하지 않는 파일 (**모든 파일 표시** 로 보이는 파일)은 시스템의 기본 응용 프로그램으로 열립니다
- 워크스페이스를 처음 열면 폴더는 접힌 상태로 시작하며, 파일, 개요, 기록 보기 사이를 전환하는 동안 열림 상태가 유지됩니다

### Quick Look

트리에서 파일을 선택하고 `Space` 를 누르면 탭을 열지 않고 창 전체를 덮는 오버레이로 미리 볼 수 있습니다 — 이미지, 비디오, 오디오는 네이티브 컨트롤과 함께 렌더링되며, 그 밖의 파일은 외부에서 열 수 있는 버튼이 있는 "미리 볼 수 없음" 패널을 표시합니다. `←`/`↑` 와 `→`/`↓` 로 트리에 보이는 파일을 순서대로 넘겨 볼 수 있으며 (처음으로 되돌아가지 않음), `Space`, `Escape` 또는 배경 클릭으로 미리보기를 닫습니다. 인라인 이름 변경 필드에서 공백을 입력해도 미리보기가 실행되지 않습니다.

### 헤더 버튼

파일 보기의 헤더에는 트리 전체에 적용되는 컨트롤이 있습니다:

- **모든 폴더 펼치기** — 트리의 모든 폴더를 엽니다
- **모든 폴더 접기** — 모든 폴더를 루트까지 다시 닫습니다
- **모든 파일 표시** — 토글이며, 켜져 있으면 (강조 표시) 트리가 VMark가 열 수 있는
  파일뿐 아니라 모든 파일을 나열합니다
- **새 파일** / **새 폴더** — 선택한 폴더 안에, 아무것도 선택하지 않았으면
  워크스페이스 루트에 만듭니다

### 파일 작업

파일, 폴더 또는 트리 아래의 빈 공간을 오른쪽 클릭하면 컨텍스트 메뉴에 접근합니다:

| 동작 | 표시 대상 | 설명 |
|------|-----------|------|
| 열기 | 파일 | 새 탭에서 파일 열기 |
| 이름 변경 | 파일, 폴더 | 파일 또는 폴더 이름 인라인 편집 (`F2`도 가능) |
| 복제 | 파일 | 파일의 복사본 만들기 |
| 이동... | 파일 | 대화상자를 통해 파일을 다른 폴더로 이동 |
| 삭제 | 파일, 폴더 | 파일 또는 폴더를 시스템 휴지통으로 이동 |
| 경로 복사 | 파일, 폴더 | 절대 경로를 클립보드에 복사 |
| Finder에서 보기 | 파일, 폴더 | 파일 관리자에서 항목 표시 — Windows에서는 **탐색기에서 보기**, Linux에서는 **파일 관리자에서 보기** 로 표시됩니다 |
| 새 파일 | 폴더, 빈 공간 | 이 위치에 새 마크다운 파일 만들기 |
| 새 폴더 | 폴더, 빈 공간 | 이 위치에 새 폴더 만들기 |
| 여기서 터미널 열기 | 폴더 | 이 폴더에서 새 터미널 세션 시작 (세션이 5개 열려 있으면 비활성화) — [터미널](/ko/guide/terminal) 참조 |

또한 트리에서 파일을 폴더 사이로 직접 **드래그 앤 드롭** 할 수 있습니다.

### 가시성 토글

기본적으로 탐색기는 VMark가 열 수 있는 파일 형식만 표시하고 점 파일을 숨깁니다.
**폴더는 보이는 내용이 있든 없든 나열되므로**, 지원하지 않는 파일 형식으로 이루어진
프로젝트는 빈 폴더들의 트리처럼 보입니다 — 이는 디렉터리를 읽지 못한 것이 아니라 필터가
작동하는 것입니다. 두 가지 토글로 이를 변경합니다:

| 토글 | 단축키 | 기능 |
|------|--------|------|
| 숨긴 파일 표시 | `Mod + Shift + .` (macOS) / `Ctrl + H` (Windows/Linux) | 점 파일 및 숨긴 폴더 표시 |
| 모든 파일 표시 | `Mod + Shift + A` | 마크다운이 아닌 파일을 문서와 함께 표시 |

두 설정 모두 워크스페이스별로 저장되며 세션 간에 유지됩니다.

### 제외된 폴더

일부 디렉터리는 워크스페이스 설정과 관계없이 절대 내용을 나열하지 않습니다 — 워크스페이스
검색에 적용되는 것과 같은 최소 기준입니다: `.git`, `node_modules`, `.obsidian`,
`.svn`, `__pycache__`, `.DS_Store`, `.vscode`, `.idea`, `target`, `.next`,
`dist`, `.superpowers`. 이 폴더들은 존재한다는 것을 알 수 있도록 폴더로는 계속 표시되지만,
그 내용은 읽지 않습니다. 워크스페이스 설정의 **제외된 폴더** 에 원하는 이름을 추가할 수
있습니다 (새 워크스페이스는 여기에 `.git`과 `node_modules`가 들어 있는 상태로 시작합니다).

트리는 한 번에 나열되고 파일이 변경되면 새로 고쳐집니다. 변경이 연달아 일어나면 그 연속이
끝난 직후 한 번만 새로 고칩니다. 변경이 멈추지 않는 폴더 (진행 중인 다운로드, 빌드, 동기화)
는 계속 새로 고치는 대신 점점 넓어지는 간격으로 새로 고치므로, 탐색기가 바쁜 워크스페이스를
다시 읽느라 CPU 코어 하나를 점유하는 일이 없습니다.

## 빠른 열기

`Mod + O`를 눌러 빠른 열기 오버레이를 엽니다. 세 가지 소스에서 다음 순서로 퍼지 검색을 제공합니다:

1. 현재 창의 **열린 탭** (점 표시기로 표시), 가장 최근에 사용한 것이 먼저
2. 이전에 연 **최근 파일**
3. 워크스페이스에서 **파일 탐색기에 현재 표시되는 모든 파일**

입력하기 전에는 목록에 열린 탭과 최근 파일만 표시됩니다. 입력을 시작하면 세 소스의 결과가 모두 나타나며, 위 순서대로 그룹화되고 각 그룹 안에서는 일치 정도에 따라 정렬됩니다.

몇 글자를 입력하여 필터링합니다 — 매칭은 퍼지 방식이므로 `rme`가 `README.md`를 찾습니다. 화살표 키로 탐색하고 **Enter** 로 엽니다. 하단의 고정된 **찾아보기...** 행이 파일 대화상자를 엽니다.

세 번째 소스는 파일 탐색기를 정확히 따르므로, 둘이 무엇이 존재하는지에 대해 서로 다르게
말하는 일은 없습니다. **숨긴 파일 표시** 를 켜면 빠른 열기가 `.claude/`, `.github/workflows/`
및 기타 점 디렉터리 아래의 문서를 찾고, **모든 파일 표시** 를 켜면 마크다운이 아닌 파일도
찾으며, 각 파일을 사이드바에서 클릭한 것과 같은 방식으로 엽니다 — VMark 자체 형식은 탭에서,
그 밖의 모든 것은 시스템의 기본 응용 프로그램에서 엽니다. 항상 건너뛰는 목록의 폴더
(`.git`, `node_modules`, `.vscode` 등) 는 두 곳 모두에서 제외됩니다.

| 동작 | 단축키 |
|------|--------|
| 빠른 열기 열기 | `Mod + O` |
| 결과 탐색 | `위 / 아래` |
| 선택한 파일 열기 | `Enter` |
| 닫기 | `Escape` |

::: tip
워크스페이스 없이도 빠른 열기는 작동합니다 — 최근 파일과 열린 탭을 표시하지만 파일 트리를 검색할 수 없습니다.
:::

## 워크스페이스 콘텐츠 검색

워크스페이스가 열려 있을 때 VMark는 (파일명뿐 아니라) **파일 콘텐츠** 전체를 검색할 수 있습니다. 기본적으로 VMark가 여는 파일 형식(마크다운, 일반 텍스트, YAML, 그리고 해당 형식 지원이 켜져 있으면 JSON/TOML/Mermaid/SVG/HTML)을 검색합니다. **.md** 토글(**지원되는 파일 형식만**)을 끄면 모든 텍스트 파일을 검색합니다(바이너리는 항상 건너뜁니다).

| 동작 | 단축키 |
|------|--------|
| 콘텐츠 검색 패널 열기 | `Mod + Shift + H` (**편집 → 찾기 → 파일에서 찾기...** 로도 가능) |
| 다음 결과로 이동 | `Enter` (또는 화살표 키로 탐색) |
| 결과를 새 탭에서 열기 | 일치 항목 미리보기 클릭 |

각 결과에는 파일 경로, 줄 번호, 일치 텍스트가 강조 표시된 스니펫이 표시됩니다. 결과에는 순위가 매겨지지 않습니다: 파일은 검색이 워크스페이스 폴더를 탐색하면서 도달한 순서대로 나열됩니다. 검색은 일치하는 파일 50개, 일치 항목 1,000개 또는 5초에 도달하면 멈추고, 그때까지 찾은 결과를 표시합니다.

**기본 제외 대상**: VMark가 절대 들어가지 않는 폴더 — `.git`, `node_modules`, `.obsidian`, `.svn`, `__pycache__`, `.DS_Store`, `.vscode`, `.idea`, `target`, `.next`, `dist`, `.superpowers` — 와 워크스페이스 설정의 **제외된 폴더** 에 있는 모든 이름 (새 워크스페이스는 여기에 `.git`과 `node_modules`가 들어 있는 상태로 시작합니다).

**숨긴 파일**: 파일 탐색기의 **숨긴 파일 표시** 토글 설정과 관계없이 콘텐츠 검색은 점 파일을 항상 건너뜁니다.

이는 *파일명* 만 검색하는 [빠른 열기](#%EB%B9%A0%EB%A5%B8-%EC%97%B4%EA%B8%B0)와 다릅니다 — 콘텐츠 검색은 일치하는 줄에 커서를 놓고 일치한 파일을 엽니다.

## 최근 워크스페이스

VMark는 최근에 열린 워크스페이스를 최대 10개까지 기억합니다. 메뉴 바의 **파일 > 최근 워크스페이스** 에서 접근합니다.

- 워크스페이스는 마지막으로 열린 시간 순으로 정렬됩니다 (가장 최근 것이 먼저)
- 목록은 모든 변경 시 기본 메뉴와 동기화됩니다
- **최근 워크스페이스 지우기** 를 선택하여 목록을 초기화합니다

## 워크스페이스 설정

각 워크스페이스에는 세션 간에 유지되는 자체 구성이 있습니다. 설정은 프로젝트 폴더 내부가 아닌 VMark 응용 프로그램 데이터 디렉터리에 저장됩니다 — 따라서 워크스페이스가 깨끗하게 유지됩니다.

다음 설정이 워크스페이스별로 저장됩니다:

| 설정 | 설명 |
|------|------|
| 제외된 폴더 | 파일 탐색기에서 숨겨진 폴더 |
| 숨긴 파일 표시 | 점 파일이 표시되는지 여부 |
| 모든 파일 표시 | 마크다운이 아닌 파일이 표시되는지 여부 |
| 마지막으로 열린 탭 | 다음 열기 시 세션 복원을 위한 파일 경로 |

::: tip
워크스페이스 구성은 폴더 경로와 연결됩니다. 동일한 기기에서 동일한 폴더를 열면 다른 창에서도 항상 설정이 복원됩니다.
:::

## 빈 워크스페이스 창

마지막으로 열린 문서를 닫아도 더 이상 창이 닫히지 않습니다. 대신 창은 **환영 화면** 으로 열린 채 유지되며, 워크스페이스가 열려 있다면 그 사이드바와 파일 트리도 계속 표시됩니다. 이는 macOS, Windows, Linux에서 동일하게 동작합니다.

환영 화면에는 작업으로 빠르게 돌아갈 수 있는 동작이 있습니다:

- **새 파일**, **파일 열기**, **워크스페이스 열기…** 버튼
- **최근 파일** 목록과 **최근 워크스페이스** 목록 — 항목을 클릭하면 다시
  엽니다. 각 목록은 항목이 있을 때만 나타납니다.

**파일 열기** 와 최근 목록은 지금 있는 창을 재사용합니다. 환영 화면 창에는 밀어낼 탭이
없으므로 두 번째 창에서 열리는 것은 없습니다 — 다만 창에 아직 워크스페이스가 열려 있다면,
그 워크스페이스 밖의 파일은 사이드바에 아직 보이는 파일 트리를 대체하는 대신 자체 창에서
열립니다.

환영 화면 창의 제목 표시줄에는 **VMark** 라고 표시됩니다: 열린 문서가 없으므로 표시할
파일 이름이 없기 때문입니다.

창 자체를 닫으려면 빨간색 신호등 버튼, `Cmd/Ctrl + Q` (종료)를 사용하거나, 환영 화면이 표시된 상태에서 `Cmd/Ctrl + W` 를 한 번 더 누르세요.

## 나란히 보는 문서

서로 **다른** 두 문서를 한 번에 엽니다 — 에디터를 두 개의 창으로 나누어 각 창에
자체 문서를 표시합니다. 이중 언어 읽기/번역 (한쪽에 원문, 다른 쪽에 번역)이나
글을 쓰는 동안 참고 자료를 열어 두는 데 유용합니다.
이는 *같은* 파일의 소스 + 미리보기인 **마크다운 분할 보기** (`Shift + F6`)와는
다릅니다.

- **`Alt + Mod + \`** 또는 명령 팔레트 (**편집기 분할 — 문서 두 개**)로 분할을
  토글합니다. 현재 문서는 한쪽 창에 그대로 있고, 그 직전에 가장 최근에 사용한
  문서 (없으면 다른 열린 문서)가 다른 쪽 창에 열립니다 — 같은 문서가 두 번
  표시되는 일은 없으므로, 분할하려면 문서가 두 개 열려 있어야 합니다.
  창에 포커스가 있을 때 탭을 클릭하면 그 창의 문서가 바뀌며, 탭을 오른쪽
  클릭하여 **옆에 열기** 를 선택할 수도 있습니다.
- 구분선을 드래그하여 (또는 포커스한 뒤 화살표 키로) 창 크기를 조절합니다.
- 편집 중인 창이 **포커스된** 창입니다 — 툴바, 찾기 바, 메뉴 명령이 이 창에
  적용됩니다.
- **분할 창 간 스크롤 동기화** (명령 팔레트)를 켜면 양쪽이 비례하여 함께
  스크롤됩니다 — 번역문을 원문과 나란히 맞출 때 편리합니다.

## 세션 복원

워크스페이스가 열려 있는 창을 닫으면 VMark가 열린 탭 목록을 워크스페이스 구성에 저장합니다. 다음에 동일한 워크스페이스를 열면 해당 탭이 자동으로 복원됩니다.

- 저장된 파일 경로가 있는 탭만 복원됩니다 (제목 없는 탭은 지속되지 않습니다)
- 마지막 세션 이후 파일이 이동되거나 삭제된 경우 자동으로 건너뜁니다
- 세션 데이터는 창을 닫을 때와 워크스페이스를 닫을 때 (`파일 > 워크스페이스 닫기`) 저장됩니다

## 멀티 창

각 VMark 창에는 자체 독립 워크스페이스가 있을 수 있습니다. 이를 통해 여러 프로젝트를 동시에 작업할 수 있습니다.

- **파일 > 새 창** 으로 새 창을 엽니다
- 새 창에서 워크스페이스를 열면 다른 창에 영향을 미치지 않습니다
- 창 크기와 위치가 창별로 기억됩니다

Finder에서 마크다운 파일을 드래그할 때 현재 창에 저장되지 않은 작업이 있으면 VMark가 자동으로 새 창에서 파일의 프로젝트를 엽니다.

### 현재 워크스페이스 밖의 파일 열기

워크스페이스가 열려 있는 창은 그 워크스페이스를 유지합니다. 다른 곳에 있는 파일을 열면 —
Finder나 탐색기에서, `파일 > 열기` 에서, 또는 최근 파일에서 — 그 파일은 자체 폴더를 루트로
하는 **새 창** 에서 열리므로, 작업하던 파일 트리는 그대로 남아 있습니다. 자체 워크스페이스가
없는 창만 그 자리에서 파일을 엽니다.

Windows와 Linux에서 VMark에 연결된 형식의 파일을 더블 클릭하면, 이제 두 번째 인스턴스를
시작하는 대신 이미 실행 중인 VMark에 파일을 넘깁니다. macOS는 항상 이렇게 동작해 왔습니다.

### 탭을 새 창으로 분리

탭을 창에서 꺼내 새 창을 만들 수 있습니다:

- **탭을 탭 바 밖으로 드래그** 하면 — 탭 바 위나 아래로 약 40px 이상 — 분리됩니다. 다른 VMark 창 위에서 놓으면 탭이 그 창으로 이동하고, 그 밖의 곳에서 놓으면 포인터 위치에 새 창으로 열립니다
- **탭을 수평으로 드래그** 하여 탭 바 내에서 다른 탭 사이의 순서를 변경합니다
- 고정된 탭은 드래그할 수 없습니다

이동이 완료되면 토스트가 표시되며 **실행 취소** 를 선택하면 탭이 원래대로 돌아옵니다. 브라우저 탭과 메인 창의 마지막 탭은 밖으로 드래그할 수 없으며, 대신 제자리로 돌아갑니다.

제스처는 방향이 고정됩니다: 수평 이동은 재정렬을 시작하고, 수직 이동은 분리를 트리거합니다. 드래그 중에 포인터를 탭 바 밖으로 이동하면 재정렬에서 분리로 전환할 수 있습니다.

### 창 상태 패널

여러 창에서 Claude Code를 실행할 때, **보기 > 창 상태 전환** (명령 팔레트에서도 가능하며, `Ctrl + Shift + 5` 를 눌러도 됨) 은 다른 모든 열린 창을 실시간 상태와 함께 나열하고 바로 그 창으로 이동할 수 있게 해 주는 패널을 엽니다.

각 행에는 창의 문서 이름과 현재 상태가 표시됩니다:

| 상태 | 의미 |
|------|------|
| **주의 필요** | 그 (포커스되지 않은) 창의 터미널이 벨을 울렸습니다 — Claude Code는 한 턴을 마치거나 사용자를 기다릴 때 벨을 울립니다 |
| **실행 중** | 그 창에서 VMark AI 지니가 현재 실행 중입니다 |
| **오류** | 마지막 AI 지니 실행이 실패했습니다 |
| **대기** | 실행 중인 것이 없습니다 |

행은 주의가 필요한 것부터 정렬되므로, 사용자가 필요한 창이 맨 위에 옵니다. 행을 클릭하면 그 창에 포커스를 주고 앞으로 가져오며, 창에 포커스를 주면 "주의 필요" 표시가 지워집니다. 상태는 터미널 출력을 파싱하는 것이 아니라 두 가지 신뢰할 수 있는 신호 — VMark 자체의 AI 지니 호출 상태와 터미널 벨 — 에서 가져옵니다.

**패널을 고정** 하면 상시 "관제 센터"로 사용할 수 있습니다: 고정된 동안에는 행을 클릭하면 대상 창에 포커스가 가지만 패널은 열린 채로 남으므로, 다시 열지 않고도 여러 창 사이를 오갈 수 있습니다. 헤더의 고정 버튼은 두 가지 범위가 있는 작은 메뉴를 엽니다:

- **이 창 고정** — 현재 창에서만 패널을 고정합니다. 열림 및 고정 상태는 재시작 후에도 창별로 기억되므로, 대시보드로 설정한 창은 그대로 유지됩니다.
- **모든 창 고정** — 전역 고정입니다: 모든 창이 자동으로 패널을 열고 고정된 것처럼 동작하며, *나중에 여는 창도 포함* 되므로, 각 창을 일일이 설정하는 대신 관제 센터 레이아웃을 한 번만 선택하면 됩니다. 이를 끄면 모든 창이 각자의 창별 고정 상태로 돌아갑니다.

## 외부 변경 사항

VMark는 다른 프로그램(Git, 외부 편집기, 빌드 도구 등)에 의한 워크스페이스 변경 사항을 모니터링하고 열린 문서를 동기화 상태로 유지합니다.

- **수정되지 않은 파일** 은 디스크의 내용이 변경되면 자동으로 다시 로드됩니다. 간단한 토스트 알림이 다시 로드를 확인합니다.
- **저장되지 않은 변경 사항이 있는 파일** 은 세 가지 옵션이 있는 프롬프트 대화상자를 표시합니다: **다른 이름으로 저장** (새 위치에 저장), **다시 로드** (변경 사항을 버리고 디스크에서 로드), 또는 **유지** (편집 내용을 보존하고 파일을 분기 상태로 표시).
- **삭제된 파일** 은 탭에서 누락으로 표시되지만 닫히지 않습니다 — 내용을 새 위치에 저장할 수 있습니다.
- 여러 수정된 파일이 동시에 변경되는 경우 (예: `git checkout` 후), VMark는 이를 하나의 대화상자로 묶어 모두 다시 로드, 모두 유지 또는 각 파일을 개별적으로 검토할 수 있게 합니다.
- 분기된 파일의 디스크 내용이 나중에 에디터의 내용과 일치하면 (예: `git checkout`이 동일한 텍스트를 복원), VMark는 자동으로 분기 상태를 지워 정상적인 자동 저장이 재개됩니다.

VMark는 자체 저장을 필터링하므로 앱 내에서 수행한 변경 사항에 대해 프롬프트가 표시되지 않습니다.

## macOS Dock 최근 문서

VMark에서 열 문서는 macOS에 등록되어 Dock에서 VMark 아이콘을 오른쪽 클릭하면 **최근 사용 항목 열기** 하위 메뉴에 나타납니다.

## 터미널 통합

통합 터미널은 자동으로 워크스페이스 루트를 작업 디렉터리로 사용합니다. 워크스페이스를 열거나 전환하면 유휴 상태의 터미널 세션이 새 루트로 `cd`합니다. 명령을 실행 중인 세션은 건드리지 않으며, 명령이 끝나면 디렉터리를 변경합니다 (세션이 실행 중인지 알려면 셸 통합이 필요합니다). [워크스페이스 레일](/ko/guide/workspace-rail)이 켜져 있으면 한 워크스페이스에 속한 세션은 자체 디렉터리를 유지합니다.

`VMARK_WORKSPACE` 환경 변수는 모든 터미널 세션에서 워크스페이스 경로로 설정되어 스크립트가 프로젝트 루트를 참조할 수 있습니다.

[터미널에 대해 자세히 알아보기 →](/ko/guide/terminal)

## 셸 CLI 명령어

VMark는 `vmark` 셸 명령어를 설치하여 터미널에서 파일과 폴더를 열 수 있게 합니다.

### 설치 및 제거

**도움말 > 셸 명령: PATH에 'vmark' 설치...** 는 토글되는 단일 항목입니다. `vmark` 명령어가 설치되어 있지 않으면 `/usr/local/bin/vmark`에 작은 런처 스크립트를 작성하고 관리자 비밀번호를 요청합니다 (VS Code가 `code` 명령어에 사용하는 것과 동일한 방식입니다). VMark 자체 스크립트가 이미 있으면 같은 항목이 그것을 제거합니다. 어느 쪽이든 대화상자가 결과를 알려 줍니다. macOS 전용입니다.

### 사용법

```bash
# 파일 열기
vmark README.md

# 폴더를 워크스페이스로 열기
vmark ~/projects/my-blog

# 여러 파일 열기
vmark chapter1.md chapter2.md
```

명령어는 `open -b app.vmark`에 위임하므로 macOS가 단일 인스턴스 동작을 처리합니다 — 파일은 새 프로세스를 시작하는 대신 기존 VMark 창에서 열립니다.

`/usr/local/bin/vmark` 의 파일을 VMark가 작성한 것이 아니라면, 이 항목은 아무것도 건드리지 않고 수동으로 제거하도록 요청합니다.
