# 설정

VMark의 설정 패널에서 에디터의 모든 측면을 사용자 정의할 수 있습니다. `Mod + ,`로 열거나 메뉴 바의 **VMark > 설정** 을 통해 접근합니다.

설정 창에는 섹션을 (영어 이름 기준) 알파벳순으로 나열한 사이드바가 있으며, 정보가 맨 아래에, 고급이 표시될 때는 그 아래에 있습니다. 변경 사항은 즉시 적용됩니다 — 저장 버튼이 없습니다.

사이드바 맨 위의 **검색 상자** 를 사용하면 모든 패널의 설정을 이름이나 설명으로 필터링할 수 있습니다 — 일치하는 행이 한데 모여 표시되므로 설정이 어느 카테고리에 있는지 몰라도 됩니다. 모든 설정을 공장 기본값으로 되돌리려면 정보 섹션의 **기본값으로 초기화** 를 사용하세요.

## 모양

시각적 테마와 창 동작을 제어합니다.

### 테마

6가지 색상 테마 중 하나를 선택합니다. 활성 테마는 색상 샘플 주위에 링으로 표시됩니다.

| 테마 | 배경 | 스타일 |
|------|------|--------|
| White | `#FFFFFF` | 깔끔한 흰색, 가장 높은 대비 |
| Paper | `#EEEDED` | 따뜻한 신문 용지 느낌 (기본값) |
| Mint | `#CCE6D0` | 부드러운 녹색, 눈이 편안함 |
| Sepia | `#F9F0DB` | 책 종이 느낌, 긴 글 읽기에 적합 |
| Night | `#23262B` | 어두운 곳을 위한 짙은 슬레이트 |
| Solarized | `#002B36` | Solarized Dark, 고전적인 팔레트 |

::: info Windows 10과 Linux에서는 White와 Night만 제공됩니다
Windows 10과 Linux에서는 시스템이 제목 표시줄을 그리며, 이는 밝거나 어두운 두 가지만 가능합니다. 그래서 이 플랫폼에서는 **White**와 **Night**만 제공되며, 시스템 크롬과 맞출 수 없는 테마는 둘 중 가까운 쪽으로 표시됩니다: Paper, Mint, Sepia는 White로, Solarized는 Night로 표시됩니다. 저장된 선택은 바뀌지 않으며 — macOS와 Windows 11에서는 전체 카탈로그를 사용할 수 있습니다. Windows 11에서는 제목 표시줄이 테마 고유의 색을 따르고, 메뉴 바는 계속 밝거나 어둡게 그려집니다.
:::

#### 시스템 화면 모드 따르기

| 설정 | 설명 | 기본값 |
|------|------|--------|
| 시스템 화면 모드 따르기 | 시스템에 따라 라이트 테마와 다크 테마를 자동으로 전환합니다 | 끄기 |

켜면 단일 테마 행이 두 행으로 바뀝니다 — **라이트 테마** (시스템이 라이트 모드일 때 사용, 기본값 Paper)와 **다크 테마** (다크 모드에서 사용, 기본값 Night). 시스템 화면 모드가 바뀌는 즉시 VMark가 둘 사이를 전환하며, 직접 선택한 테마는 보관되었다가 이 옵션을 끄면 복원됩니다.

### 사이드바

| 설정 | 설명 | 기본값 | 옵션 |
|------|------|--------|------|
| 사이드바 스타일 | 사이드바와 작업 공간 레일의 테두리 방식입니다. **전체 높이**는 macOS 기본 사이드바처럼 얇은 구분선과 함께 창 가장자리에 붙여 표시하고, **카드**는 둥근 모서리와 그림자로 창 안에 띄워 표시합니다. 설정 창에도 적용됩니다 | 전체 높이 | 전체 높이, 카드 |

### 창

| 설정 | 설명 | 기본값 |
|------|------|--------|
| 제목 표시줄에 파일명 표시 | macOS 창 제목 표시줄에 현재 파일명 표시. **macOS 전용** — Windows와 Linux는 시스템 제목 표시줄에 항상 파일명을 표시하므로 다른 플랫폼에서는 이 설정이 숨겨집니다 | 끄기 |

macOS에서는 VMark가 시스템 제목 표시줄 위에 자체 제목 표시줄을 그리므로, 파일명은
그 영역에 선택적으로 넣는 요소입니다. Windows와 Linux에서는 시스템이 창 위에 실제
제목 표시줄을 그립니다: 파일명(저장되지 않은 변경 사항이 있으면 `•` 포함)은 항상
그곳에 나타나며, VMark는 자체 제목 영역을 추가하지 않습니다.

#### 직접 설치한 폰트 사용하기

위에 나열된 이름은 추천 목록일 뿐 한계가 아닙니다. 세 가지 폰트 선택기에는 각각
이 컴퓨터의 모든 폰트 패밀리를 나열하는 **설치된 폰트** 섹션도 있어서, 직접 설치한
글꼴 — LXGW WenKai, Iosevka, Source Han Serif — 도 기본 제공 폰트와 같은 방식으로
선택할 수 있습니다.

목록 끝의 **사용자 지정…** 을 선택하면 패밀리 이름을 직접 입력할 수 있습니다.
시스템이 표시하는 이름을 정확히 사용하세요 (macOS: 서체 관리자, Windows: 설정 →
개인 설정 → 글꼴) — LXGW WenKai / 霞鹜文楷의 경우 `LXGW WenKai`입니다. 이름이
완성되는 즉시 폰트가 적용되며, 아무것도 바뀌지 않는다면 그 이름이 설치된 패밀리와
일치하지 않는 것입니다. 따옴표, 쉼표, 세미콜론, 괄호가 포함된 이름은 거부되며, 해당
행에 그 사실이 표시됩니다.

::: tip 설치된 폰트는 macOS 전용입니다
macOS는 설치된 모든 패밀리를 나열해 줍니다. Windows와 Linux에서는 이 섹션이 비어
있으며 **사용자 지정…** 으로 입력하면 됩니다 — 패밀리 이름 입력은 세 플랫폼 모두에서
똑같이 작동합니다.
:::

선택한 폰트는 같은 엔진과 같은 폰트로 렌더링하는 PDF 내보내기에도 그대로 적용됩니다.
HTML 내보내기는 컴퓨터의 폰트를 포함할 수 없으므로, 내보낸 페이지는 독자가 같은
패밀리를 설치하지 않은 한 독자 자신의 폰트로 대체됩니다.

### 표시

| 설정 | 설명 | 기본값 | 옵션 |
|------|------|--------|------|
| 에디터 너비 | 최대 콘텐츠 너비. 더 넓은 값은 대형 모니터에 적합하고, 더 좁은 값은 가독성을 향상시킵니다 | 50em (중간) | 36em (컴팩트), 42em (좁은), 50em (중간), 60em (넓은), 80em (매우 넓음), 무제한 |

::: tip 같은 너비라도 라틴 문자와 CJK는 다르게 읽힙니다
에디터 너비는 `em` 단위이므로 *글자 수* 기준 줄 길이는 문자 체계에 따라 달라집니다: 50em에서 라틴 문자 한 줄은 대략 90–100자(조판에서 권장하는 45–75자의 약 2배로, 두 창 편집기에 적합)를 담고, CJK 한 줄은 전각 문자 약 50자를 담습니다 — 중국어 텍스트의 전통적인 40–60자 범위에 딱 맞습니다. 주로 라틴 문자로 산문을 쓰면서 책 같은 줄 길이를 원한다면 36–42em을 선택하세요. 주로 CJK 문서라면 기본값이 이미 고전적인 줄 길이입니다.
:::

::: tip
18px 글꼴 크기에서 50em은 약 900px입니다 — 대부분의 화면에서 편안한 읽기 너비입니다.
:::

| 복사 형식 | WYSIWYG 모드에서 복사할 때 일반 텍스트 클립보드 슬롯에 사용할 형식 | 일반 텍스트 | 일반 텍스트, 마크다운 |

| 이미지 및 테이블 정렬 | 블록 이미지와 테이블의 수평 정렬. 에디터 전용 — 내보내기나 인쇄에는 적용되지 않음 | 중앙 | 중앙, 왼쪽 |

### HTML 렌더링

| 설정 | 설명 | 기본값 | 옵션 |
|------|------|--------|------|
| 리치 텍스트에서 원시 HTML | WYSIWYG 모드에서 원시 HTML 블록을 렌더링할지 여부 | 새니타이즈 | 숨김, 새니타이즈, 새니타이즈 + 스타일 |
| 허용할 HTML 태그 | 렌더링되는 태그 집합의 범위 | 엄격 | 엄격, 확장 |
| 추가로 허용할 태그 | 추가로 허용할 태그 이름 (쉼표로 구분) | _(비어 있음)_ | 예: `kbd, samp, var` |

::: tip
**숨김** 은 원시 HTML을 접고 아무것도 렌더링하지 않습니다. **새니타이즈** 는 위험한 태그를 제거하고 HTML을 렌더링합니다. **새니타이즈 + 스타일** 은 추가로 인라인 `style` 속성 중 안전한 일부를 보존합니다.

**엄격** 은 작고 보수적인 태그 집합만 허용합니다. **확장** 은 추가로 `<svg>` (및 안전한 하위 요소), `<figure>`/`<figcaption>`, `<details>`/`<summary>` 및 기타 시맨틱/구조 태그를 렌더링합니다 — 모두 여전히 새니타이즈됩니다. 그 위에 특정 태그를 더하려면 **추가로 허용할 태그** 를 사용하세요 (예: `kbd, samp, var`).
:::

::: warning
이 설정과 관계없이 위험한 태그(`<script>`, `<style>`, `<iframe>`, `<form>`, 이벤트 핸들러, …)는 **항상** 제거됩니다 — 사용자 지정 태그 필드로 이를 다시 허용할 수 없습니다. 허용 목록의 범위는 WYSIWYG 미리 보기에만 영향을 주며, 파일의 원시 HTML은 절대 수정되지 않습니다.
:::

저장됩니다.

| 설정 | 설명 | 기본값 |
|------|------|--------|
| 숨긴 파일 표시 | 파일 탐색기 사이드바에 점 파일 및 숨긴 시스템 항목 포함 | 끄기 |
| 모든 파일 표시 | 파일 탐색기에 마크다운이 아닌 파일 표시. 마크다운이 아닌 파일은 시스템 기본 응용 프로그램으로 열립니다 | 끄기 |
| 파일 확장자 표시 | 사이드바, 탭 표시줄, 제목 표시줄에 전체 파일 이름 — `notes`가 아니라 `notes.md` — 을 표시합니다. 워크스페이스 여부와 관계없이 모든 곳에 적용됩니다 | 켜기 |

**파일 확장자 표시** 를 끄면 VMark가 인식하는 확장자만 숨겨집니다. VMark가 열 수
없는 파일은 어느 쪽이든 확장자가 유지되므로, 보이는 이름은 항상 디스크에 실제로
존재하는 이름입니다.

### 종료 동작

| 설정 | 설명 | 기본값 |
|------|------|--------|
| 종료 확인 | 실수로 종료하는 것을 방지하기 위해 `Cmd+Q` (또는 `Ctrl+Q`)를 두 번 눌러 종료 필요 | 켜기 |
| 닫을 때 트레이로 최소화 | **Windows 전용.** 마지막 창을 닫으면 종료하는 대신 VMark가 시스템 트레이에서 계속 실행됩니다 | 끄기 |

**닫을 때 트레이로 최소화** 는 *마지막* 창에만 영향을 줍니다. 여러 창이 열려 있을 때 하나를 닫으면 그 창은 그대로 닫힙니다. 예전에 VMark를 종료하던 마지막 닫기만이 이제 트레이로 보내는 동작이 됩니다. 아무것도 닫히지 않으므로 저장하지 않은 작업은 그대로 남아 있습니다.

- 트레이 아이콘을 **왼쪽 클릭** 하면 VMark가 다시 나타납니다.
- **오른쪽 클릭** 하면 **VMark 표시** 와 **VMark 종료** 가 나옵니다. 트레이에서 종료하면 먼저 창을 다시 표시하므로, 저장하지 않은 변경 사항 확인 창이 응답할 수 있는 곳에 나타납니다.
- `Ctrl+Q`는 여전히 평소처럼 종료합니다.
- VMark가 트레이에 있는 동안 이 설정을 끄면 아이콘이 사라지기 전에 창이 다시 나타나므로, 창도 아이콘도 없이 VMark가 실행되는 상태는 생기지 않습니다.

이 설정은 macOS와 Linux에서는 나타나지 않습니다.

## 통합

MCP 서버 및 AI 제공자 구성.

### MCP 서버

MCP (Model Context Protocol) 서버는 Claude Code, Cursor와 같은 외부 AI 어시스턴트가 VMark를 프로그래밍 방식으로 제어할 수 있게 합니다.

| 설정 | 설명 | 기본값 |
|------|------|--------|
| MCP 서버 활성화 | MCP 서버를 시작하거나 중지합니다. 실행 중일 때 포트와 연결된 클라이언트를 보여주는 상태 배지가 표시됩니다 | 켜기 (토글) |
| 시작 시 실행 | VMark가 열릴 때 MCP 서버 자동 시작 | 켜기 |
| 새 위치로 저장 및 지니 결과 자동 승인 | MCP 클라이언트가 묻지 않고 문서를 새 위치에 저장할 수 있게 하고, 지니가 미리보기를 표시하는 대신 결과를 바로 적용하게 합니다. 끄면 새 경로에 저장하라는 MCP 요청은 거부되고 토스트 알림이 표시됩니다. MCP 문서 쓰기는 이 설정의 제한을 받지 않습니다 — 각 쓰기는 에이전트 편집 기록에 기록되며 상태 표시줄의 MCP 쓰기 기록에서 복원할 수 있습니다 | 끄기 |

서버가 실행 중일 때 패널에도 다음이 표시됩니다:
- **포트** — 자동으로 할당됨; AI 클라이언트는 설정 파일을 통해 검색
- **버전** — MCP 서버 사이드카 버전
- **도구 / 리소스** — 사용 가능한 MCP 도구 및 리소스 수
- **연결된 클라이언트** — 현재 연결된 AI 클라이언트 수

MCP 서버 섹션 아래에서 단 한 번의 클릭으로 지원되는 AI 클라이언트 (Claude Desktop, Claude Code, Codex CLI, Gemini CLI)에 VMark의 MCP 설정을 설치할 수 있습니다.

자세한 내용은 [MCP 설정](/ko/guide/mcp-setup) 및 [MCP 도구 참조](/ko/guide/mcp-tools)를 참조하세요.

### AI 제공자

[AI 지니](/ko/guide/ai-genies)를 구동하는 AI 제공자를 구성합니다. 한 번에 하나의 제공자만 활성화할 수 있습니다.

**CLI 제공자** — 로컬에 설치된 AI CLI 도구 (Claude, Codex, Gemini)를 사용합니다. **감지** 를 클릭하여 `$PATH`에서 사용 가능한 CLI를 스캔합니다. CLI 제공자는 구독 플랜을 사용하며 API 키가 필요하지 않습니다.

**REST API 제공자** — API에 직접 연결합니다: Anthropic, OpenAI, **OpenAI 호환** 서비스 (DeepSeek, Groq, OpenRouter, …), Google AI, 또는 로컬 Ollama 서버 (Ollama API). 각각 모델명과 API 키가 필요합니다 — 단, Ollama는 API 키가 선택 사항입니다. Google AI를 제외한 모든 제공자는 엔드포인트도 받으며, 표준 엔드포인트가 있는 경우 미리 채워져 있습니다 (OpenAI 호환 슬롯에는 없으므로 직접 입력합니다).

각 제공자에 대한 자세한 설정 지침은 [AI 제공자](/ko/guide/ai-providers)를 참조하세요.

## 형식

비기본 형식 어댑터를 위한 옵트인 토글과, 읽기 전용 코드 탭을 위한 외부 에디터 명령입니다.

Markdown, 일반 텍스트, YAML/YML 은 **항상** 등록되어 있습니다 — 기본값입니다. 그 외의 어댑터는 모두 **기본적으로 비활성화**되어 있어, 업그레이드 시 기존 사용자가 예상치 못한 변경을 겪지 않도록 합니다. 토글을 전환하면 레지스트리가 즉시 재빌드되고, 열려 있는 탭이 적절한 어댑터로 다시 마운트됩니다 — 재시작이 필요 없습니다.

전체 형식 목록과 미리보기는 [지원 형식](/ko/guide/formats)을 참조하세요.

### 형식 지원

| 토글 | 기본값 | 활성화 대상 |
|---|---|---|
| **데이터 형식** | 끄기 | `.json`, `.jsonl`, `.toml` — 소스 + 탐색 가능한 트리 분할 창. `Cargo.toml`, `package.json`, `pyproject.toml` 스키마 인식 미리보기. |
| **다이어그램 & SVG** | 끄기 | `.mmd` (Mermaid) 및 `.svg` — 소스 + 새니타이즈된 라이브 렌더 분할 창. |
| **HTML 미리보기** | 끄기 | `.html` 및 `.htm` — 샌드박스 iframe 미리보기 (`sandbox=""` 빈 허용 목록, DOMPurify, CSP `<meta>`). 보안 승인은 아직 대기 중이며, 미리보기에 그 사실이 표시됩니다 — [HTML 보안 모델](/ko/guide/formats#html-보안-모델) 참조. |
| **코드 뷰어** | 끄기 | 읽기 전용 뷰어 12종 (`.ts`, `.tsx`, `.js`, `.jsx`, `.py`, `.rs`, `.go`, `.css`, `.sh`, `.bash`, `.rb`, `.lua`). **편집 활성화** 및 **외부 편집기에서 열기** 버튼이 있는 구문 강조 뷰어로 열림. |

카테고리가 비활성화된 경우, 해당 확장자는 일반 텍스트 폴백으로 열립니다 — 스키마 뷰 없이도 파일은 계속 열립니다.

### 기본 보기 모드

미리 보기를 지원하는 파일(HTML, SVG, Mermaid, JSON, YAML, TOML)은 세 가지
[보기 모드](/ko/guide/formats#보기-모드-소스-분할-미리-보기) 중 하나로 열립니다:

| 옵션 | 결과 |
|---|---|
| **소스** | 편집 가능한 소스 창, 전체 너비. |
| **분할** (기본값) | 소스와 미리 보기를 나란히 표시. |
| **미리 보기** | 읽기 전용 렌더링, 전체 너비. |

이는 새로 여는 탭의 기본값입니다. 각 탭은 자신의 선택을 기억하며, 화면의 토글이나
`F6` / `Shift + F6`으로 어떤 탭이든 전환할 수 있습니다.

### 외부 에디터

읽기 전용 코드 탭의 **외부 편집기에서 열기** 버튼으로 실행할 에디터를 지정합니다: 알려진 에디터의 이름 (`code`, `zed`, `subl`, `vim`, …) 또는 앱 번들 (예: `/Applications/Visual Studio Code.app`) 이나 실행 파일의 전체 경로를 입력합니다. 셸, 인터프리터, 터미널 에뮬레이터는 거부되며, 존재하지 않는 경로도 거부됩니다.

GUI 설정이 환경 변수보다 우선합니다 — 명시적인 것이 암묵적인 것보다 우선합니다. 비워 두면 환경 변수 폴백 체인 `$VMARK_EXTERNAL_EDITOR → $VISUAL → $EDITOR → 플랫폼 기본값`을 사용합니다. 전체 해석 순서와 보안 게이트는 [외부 에디터에서 열기](/ko/guide/formats#외부-에디터에서-열기)를 참조하세요.

### 일회성 업그레이드 안내

다중 형식 지원으로 업그레이드한 후 첫 실행 시, VMark는 **설정 → 형식**으로 안내하는 비차단 토스트 알림을 표시합니다. 이 알림은 설치당 한 번만 표시됩니다 — 한 번 표시되거나 닫히면 다시는 나타나지 않습니다.

### 파일 형식 재정의

카테고리 토글 외에도, 명령 팔레트의 **파일 형식 설정: 일반 텍스트 / Markdown / 기본값으로 재설정** 으로 개별 파일 계열이 열리는 방식을 재정의할 수 있습니다. 재정의는 파일 계열별로(확장자 기준, 또는 `.env` 같은 파일은 점 파일 이름 기준) 저장되며 세션이 바뀌어도 유지됩니다. [VMark가 파일 형식을 결정하는 방법](/ko/guide/formats#vmark가-파일-형식을-결정하는-방법)을 참조하세요.

**형식** 패널에는 설정한 모든 재정의가 `key → format` 형태로 나열됩니다. 항목 하나는 `×` 버튼으로 제거하고, **모두 지우기** 로 한 번에 모두 삭제할 수 있습니다 — 제거된 항목은 기본 제공 규칙으로 되돌아갑니다.

언어 섹션에는 20개 이상의 세밀한 서식 토글이 포함되어 있습니다. 예시가 포함된 각 규칙에 대한 전체 설명은 [CJK 서식](/ko/guide/cjk-formatting)을 참조하세요.

## 단축키

모든 키보드 단축키를 보고 사용자 정의합니다. 단축키는 카테고리별로 그룹화됩니다 (파일, 편집, 보기, 서식 등).

- **검색** — 이름, 카테고리, 또는 키 조합으로 단축키 필터링
- **단축키 클릭** — 키 바인딩을 변경합니다. 새 조합을 누른 다음 확인
- **초기화** — 개별 단축키를 기본값으로 복원하거나 모두 한 번에 초기화
- **내보내기 / 가져오기** — 사용자 정의 바인딩을 JSON 파일로 저장하고 다른 기기에서 가져오기

기본 단축키 전체 참조는 [키보드 단축키](/ko/guide/shortcuts)를 참조하세요.

## 터미널

통합 터미널 패널을 구성합니다. `` Ctrl + ` ``로 터미널을 엽니다.

| 설정 | 설명 | 기본값 | 옵션 |
|------|------|--------|------|
| 셸 | 사용할 셸. 적용하려면 터미널 재시작 필요. 저장된 셸을 더 이상 사용할 수 없으면 *(사용 불가)* 로 표시되고 기본값이 사용됩니다 | 시스템 기본값 | 시스템에서 자동 감지된 셸 (예: zsh, bash, fish) |

| 터미널 벨 | 터미널 벨(BEL)을 알리는 방식. **시각적** 은 세션 탭에 백그라운드 활동을 표시하고, **소리** 는 부드러운 비프음을 재생하며 (백그라운드 세션이면) 탭에도 표시를 붙여 찾을 수 있게 합니다. **끄기** 는 무시합니다. 실행 중인 세션에 즉시 적용됩니다 | 시각적 | 끄기, 시각적, 소리 |
| 비활성 창일 때 알림 | VMark 창에 포커스가 없을 때 그 창의 터미널이 벨을 울리면 (창의 문서 이름을 담은) OS 알림을 표시합니다 — 예: Claude Code가 한 턴을 마쳤을 때. 각 창을 지켜보지 않고도 여러 창의 Claude Code를 추적할 수 있습니다. 처음 사용할 때 알림 권한을 허용해야 합니다 | 켜기 | 켜기 / 끄기 |
| 최소 대비 | 흐린 터미널 텍스트를 배경 대비 최소 명암비까지 끌어올립니다. 가독성을 위해 높이고, **끄기** 로 보정을 해제합니다. 실행 중인 세션에 즉시 적용됩니다 | WCAG AA (4.5:1) | 끄기, WCAG AA (4.5:1), WCAG AAA (7:1), 최대 |

세션, 키보드 단축키, 셸 환경에 대한 자세한 내용은 [통합 터미널](/ko/guide/terminal)을 참조하세요.

## 정보

앱 버전, 웹사이트 및 GitHub 저장소 링크, 업데이트 관리를 표시합니다. **타사 고지** 링크는 VMark에 포함된 오픈 소스 소프트웨어의 라이선스 전문을 텍스트 파일용 시스템 기본 앱으로 엽니다.

### 업데이트

| 설정 | 설명 | 기본값 | 옵션 |
|------|------|--------|------|
| 자동 업데이트 | 주기적으로 새 버전 확인 | 켜기 | 켜기 / 끄기 |
| 확인 주기 | 업데이트를 확인하는 빈도. 자동 업데이트가 켜져 있을 때만 사용 가능 | 시작 시 | 시작 시, 매일, 매주, 수동만 |
| 업데이트 자동 다운로드 | 사용 가능할 때 새 버전을 백그라운드에서 다운로드 | 끄기 | 켜기 / 끄기 |
| 지금 확인 | 업데이트 확인 수동 트리거 | — | — |

업데이트가 가능하면 새 버전 번호, 릴리스 날짜, 릴리스 노트가 포함된 카드가 나타납니다. 업데이트를 **다운로드** 하거나, 이 버전을 **건너뛰거나**, 다운로드 후 **재시작하여 업데이트** 할 수 있습니다.

#### 업데이트는 VMark를 설치한 방식을 따릅니다

업데이터는 플랫폼마다 고정된 형식이 아니라, 설치할 때 사용한 것과 같은 패키지 형식을 다운로드합니다:

| 설치한 형식 | 업데이터가 가져오는 것 |
|---|---|
| macOS `.dmg` | 서명된 앱 번들 |
| Windows `.exe` (NSIS) | `.exe` 설치 프로그램 |
| Windows `.msi` | `.msi` 패키지 |
| Linux `.deb` | `.deb` 패키지 |
| Linux `.rpm` | `.rpm` 패키지 |
| Linux AppImage | AppImage |

Linux에서 `.deb` 또는 `.rpm` 설치를 업데이트하면 시스템 패키지 관리자가 실행되므로 인증을 요청받습니다 — 시스템 패키지를 설치하려면 root 권한이 필요합니다. AppImage 업데이트는 파일을 제자리에서 교체하므로 인증 요청이 없습니다.

#### 업데이트가 멈춘 경우

확인과 다운로드는 모두 네트워크를 거치므로, 곧바로 실패하지 않고 멈춰 버린 연결은 업데이트를 영원히 진행 중 상태로 남겨 둘 수 있습니다. 확인이 1분 동안, 또는 다운로드나 설치가 3분 동안 진행되지 않으면, VMark는 문서 창에 고정된 **업데이트가 멈춤** 알림을 표시합니다. 그 **다시 시도** 버튼은 업데이터를 대기 상태로 되돌려 다시 시도할 수 있게 합니다 — 이 섹션의 **지금 확인** 이나 다음 자동 확인이 새 확인부터 다시 시작합니다.

업데이트 활동은 로그 파일에 기록되므로, 문제가 반복되면 로그를 버그 신고에 첨부할 만합니다:

| 플랫폼 | 로그 위치 |
|---|---|
| macOS | `~/Library/Logs/app.vmark/` |
| Windows | `%LOCALAPPDATA%\app.vmark\logs\` |
| Linux | `~/.local/share/app.vmark/logs/` |

### 초기화

| 설정 | 설명 |
|------|------|
| 기본값으로 초기화 | 이 창들의 설정을 기본값으로 복원합니다. 먼저 확인 프롬프트가 나타납니다 — 이 작업은 취소할 수 없습니다 |

별도로 저장되어 초기화되지 **않는** 것이 세 가지 있습니다: 키보드 단축키 사용자 지정([단축키](#단축키) 창의 **모두 초기화** 사용), AI 제공자 구성, 워크스페이스별 파일 브라우저 설정(**숨긴 파일 표시**, **모든 파일 표시**). 인터페이스 언어는 시스템 언어로 돌아갑니다.

### 링크 프로토콜

| 설정 | 설명 | 기본값 |
|------|------|--------|
| 사용자 정의 링크 프로토콜 | VMark가 링크로 취급하는 추가 URL 프로토콜. 각 프로토콜을 태그로 입력합니다 | `obsidian`, `vscode`, `dict`, `x-dictionary` |

이 목록은 두 가지 역할을 합니다. 링크를 삽입할 때, 이 프로토콜 중 하나를 쓰는 클립보드 URL은 `https://`처럼 링크로 인식됩니다. 그리고 링크를 열 때, VMark는 프로토콜이 `http`, `https`, `mailto`이거나 이 목록에 있을 때만 시스템에 넘깁니다 — 그래서 `obsidian://open?vault=...` 및 `vscode://file/...` 링크는 해당 앱에서 열리고, 그 밖의 프로토콜은 거부됩니다. `javascript:`, `data:`, `file:` 등 일부 프로토콜은 목록에 무엇이 있든 이 방법으로 절대 허용되지 않습니다.

제거한 기본 프로토콜은 제거된 채로 남습니다. 이후 VMark 버전에서 추가된 기본 프로토콜은 그 버전을 처음 실행할 때 목록에 한 번 추가됩니다.

### 워크플로우

GitHub Actions 뷰어에는 스위치가 없습니다: `.github/workflows/` 아래의 파일을 열면 그래프와 폼 편집기가 표시되고,
소스 창 보조 기능(표현식 자동 완성, 커서-캔버스 동기화, `uses:` 정의로 이동)도 함께 로드됩니다.
여기에 남은 것은 뷰어의 유일한 환경설정 하나와 별도의 실행 엔진입니다.

| 설정 | 설명 | 기본값 | 옵션 |
|------|------|--------|------|
| 저장 시 YAML 서식 유지 | 폼 패널을 통한 워크플로우 편집을 저장할 때, CST 왕복 파이프라인을 통해 원본 YAML의 주석, 앵커, 키 순서, 빈 줄을 보존합니다. 끄기일 때 저장은 컴팩트 직렬화 도구를 사용합니다 (더 빠르지만 손실 발생) | 켜기 | 켜기 / 끄기 |
| 워크플로우 엔진 | VMark 고유의 YAML 워크플로우 파일을 실행합니다: 워크플로우 파일을 열면 소스 옆에 단계 그래프와 실행 / 취소 도구 모음이 표시되고, 워크플로우 지니를 실행할 수 있습니다. 단계는 AI 제공자를 호출하고 파일을 쓸 수 있으므로, 직접 요청하기 전까지는 꺼진 상태로 유지됩니다 | 끄기 | 켜기 / 끄기 |

엔진은 뷰어에 표시되는 내용을 바꾸지 않습니다: GitHub Actions 파일은 엔진과 상관없이 뷰어에서 열리며,
엔진이 꺼져 있으면 VMark 워크플로우 파일은 일반 YAML 트리로 표시됩니다. 또한 엔진이 꺼져 있으면
VMark는 버튼을 숨기는 데 그치지 않고 워크플로우 실행 요청을 — MCP로 들어오는 요청까지 포함해 —
아예 거부하며, "워크플로 엔진이 설정에서 꺼져 있습니다"라고 알립니다.

두 행 모두 **개발자 도구**(아래 참조) 아래에 있습니다 — 개발자 도구를 켜야 표시됩니다.
뷰어는 [워크플로우 뷰어](/ko/guide/workflow-viewer)를, 엔진은 [Genie 워크플로](/ko/guide/workflows)를 참조하세요.

| 설정 | 설명 | 기본값 | 옵션 |
|------|------|--------|------|

설정 행은 브라우저 토글이 켜져 있을 때만 나타나며, 토글이 켜져 있다고 해서 바뀌지
않습니다 — 직접 바꾸기 전까지 샌드박스 / 루프백 차단 상태로 유지됩니다. 전체 기능
표면은 [내장 브라우저](/ko/guide/browser)를 참조하세요.

### 개발자 도구

**개발자 도구** 는 실험적 설정과 개발 전용 설정을 위한, 저장되는 마스터 스위치입니다.
켜면 **저장 시 YAML 서식 유지** 행, **워크플로 엔진** 토글, 그리고 **핫 종료 개발자
도구** 패널(세션 캡처, 검사, 복원, 지우기, 재시작을 테스트하는 버튼)이 나타납니다.
스위치 상태가 저장되므로, 켜 둔 진행 중인 기능은 세션이 바뀌어도, 릴리스 빌드에서도
계속 접근할 수 있습니다 — 설정을 열 때마다 개발자 도구를 다시 켤 필요가 없습니다.

설정 밖에서는 [지식 베이스](/ko/guide/knowledge-base)도 표시합니다: **보기 → 지식
베이스 전환** 메뉴 항목, 명령 팔레트 명령, `Ctrl + Shift + 4` 단축키는 개발자 도구가
켜질 때까지 숨겨집니다. 어느 플랫폼의 릴리스 빌드에도 그 기능에 필요한 콘텐츠 서버
런타임이 포함되어 있지 않기 때문입니다.

| 설정 | 설명 | 기본값 |
|------|------|--------|
| 개발자 도구 | 개발자 모드를 켜고 아래의 실험적 설정과 개발 전용 설정을 표시합니다 | 끄기 |
