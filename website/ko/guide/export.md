# 내보내기 및 인쇄

VMark는 문서를 내보내고 공유하는 여러 방법을 제공합니다.

## 내보내기 결과물

**파일 → 내보내기 → HTML...** 은 문서 이름을 딴 폴더 하나를 만들며, 그 안에는 항상 다음 두 파일이 **모두** 들어 있습니다 — 선택할 모드는 없습니다:

```text
MyDocument/
├── index.html          ← assets/ 아래 파일에 링크
├── standalone.html     ← 모든 것을 데이터 URI로 포함 (CSS, JS, 이미지, 폰트)
└── assets/
    ├── vmark-reader.css
    ├── vmark-reader.js
    ├── images/
    │   ├── image1.png
    │   └── ...
    └── fonts/          ← 문서에 수식이 있거나 웹 폰트를 사용할 때만
```

상황에 맞는 파일을 사용하세요:

| 파일 | 적합한 용도 | 단점 |
|------|------------|------|
| `index.html` | 정적 사이트 호스팅 (깔끔한 `/MyDocument/` URL), 다른 도구에서 편집, 용량 줄이기 | 옆에 `assets/` 폴더가 있어야 함 |
| `standalone.html` | 이미지가 사라지면 안 되는 단일 파일을 이메일이나 메신저로 보내기 | 더 큼 — 모든 에셋이 인라인으로 포함됨 |

두 파일 모두 에디터가 사용하는 것과 같은 WYSIWYG 렌더러와 스타일시트로 렌더링되며, 둘 다 [VMark Reader](#vmark-reader)를 포함합니다.

## 내보내는 방법

### HTML 내보내기

1. **파일 → 내보내기 → HTML...** 사용
2. 저장 위치를 고르고 이름을 입력합니다 — 이 이름이 폴더 이름이 됩니다 (끝의 `.html`은 제거됨)
3. 새 폴더에서 `index.html` 또는 `standalone.html`을 엽니다

#### 이전에 사용한 폴더로 다시 내보내기

HTML 내보내기는 전부 아니면 전무입니다. 모든 파일은 먼저 선택한 대상 안의 임시
`.vmark-export-…` 폴더에 기록되고, 모든 파일이 준비된 뒤에야 제자리로 옮겨집니다 —
따라서 도중에 실패한 내보내기는 이전 내보내기를 절반만 덮어쓰지 않고 원래 상태
그대로 남겨 둡니다.

보게 될 수 있는 두 가지:

- **"Another export is already writing to this folder."** 창에 상관없이 한 번에
  하나의 내보내기만 폴더에 쓸 수 있습니다. 다른 내보내기가 끝날 때까지 기다리거나,
  — 실행 중인 다른 작업이 없다면 — 메시지에 표시된 `.vmark-export.lock` 파일을
  삭제하고 다시 시도하세요.
- **남아 있는 `.vmark-export-…` 폴더.** VMark는 작업이 끝나면 이 폴더를
  제거합니다. 이전 파일을 되돌리는 작업마저 실패한 경우에만 남으며, 이때 폴더에는
  그 파일들이 들어 있고 오류 메시지에 정확한 위치가 표시됩니다. 그것이 유일한
  사본인 동안에는 아무것도 삭제되지 않습니다.

### 인쇄 / PDF 내보내기

macOS, Windows, Linux에서 사용할 수 있습니다.

**PDF 내보내기** (**파일 → 내보내기 → PDF...**) 는 내보내기 대화상자에서 선택한
페이지 크기, 방향, 여백, 타이포그래피를 사용하여 PDF를 직접 만듭니다.

**인쇄** (`Cmd/Ctrl + P` 또는 **파일 → 인쇄...**) 는 대신 시스템 인쇄 대화상자를
열어, 문서를 프린터로 보내거나 운영 체제 자체의 "PDF로 저장"을 사용할 수 있게
합니다. macOS와 Linux에서는 인쇄 작업이 끝나면 VMark가 짧은 알림으로 확인해 주고,
대화상자를 취소하면 아무것도 표시하지 않습니다. Windows의 인쇄 UI는 결과를 알려
주지 않으므로 Windows에서는 알림이 표시되지 않습니다.

내보내기 대화상자는 세 플랫폼 모두에서 같은 진행 단계 — 불러오는 중, 생성 중,
마무리 중, 완료 — 를 표시합니다.

::: info macOS의 페이지 크기
대화상자에서 고른 페이지 크기와 방향이 모든 플랫폼에서 내보낸 페이지를 결정합니다.
macOS에서는 시스템에 설정된 용지 크기보다 우선합니다 — Mac의 기본값이 Letter이고
A4를 선택하면 PDF는 A4가 됩니다.
:::

**사이드바 개요.** 내보낸 PDF에는 세 플랫폼 모두에서 제목 개요 — PDF 뷰어가
사이드바에 표시하는 클릭 가능한 목차 — 가 포함됩니다.

#### 페이지 번호

대화상자의 **페이지 번호** 섹션은 각 페이지에 번호를 추가합니다. 기본적으로 켜져
있으며 하단 가운데에 표시됩니다.

| 설정 | 옵션 |
|------|------|
| 위치 | 하단 가운데, 하단 오른쪽, 또는 끄기 |
| 형식 | `7`, `7 / 12`, 또는 `Page 7 of 12` |
| 첫 페이지 건너뛰기 | 1페이지에 번호를 붙이지 않음 — 표지 페이지의 일반적인 처리 방식 |

번호는 선택한 하단 여백 안에 위치하며 본문 폰트 크기에 맞춰 크기가 조정됩니다.
번호는 항상 실제 페이지를 반영하므로, 첫 페이지를 건너뛰면 다음 페이지들은 번호를
다시 매기지 않고 2, 3, 4…가 됩니다.

::: info 페이지 번호는 라틴 문자를 사용합니다
번호는 어떤 뷰어도 다운로드할 필요가 없는 표준 PDF 폰트로 그려지며, 그래서
내보내기가 빠르고 자체 완결적입니다 — 하지만 이 폰트는 중국어, 일본어, 한국어,
키릴 문자를 렌더링할 수 없습니다. 두 가지 숫자 형식은 모든 언어에서 작동합니다.
인터페이스 언어가 `Page 7 of 12`를 그 폰트로 그릴 수 없는 문자로 표기한다면,
VMark는 빈칸이나 잘못된 문자 대신 숫자 형식인 `7 / 12`를 인쇄합니다.
:::

### 다른 형식으로 내보내기

VMark는 [Pandoc](https://pandoc.org/) — 범용 문서 변환기 — 과 통합하여 마크다운을 추가 형식으로 내보낼 수 있습니다. 메뉴에서 직접 형식을 선택합니다:

**파일 → 내보내기 → Pandoc 사용 →**

| 메뉴 항목 | 확장자 |
|----------|--------|
| Word (.docx) | `.docx` |
| EPUB (.epub) | `.epub` |
| LaTeX (.tex) | `.tex` |
| OpenDocument (.odt) | `.odt` |
| 서식 있는 텍스트 (.rtf) | `.rtf` |
| 일반 텍스트 (.txt) | `.txt` |

**설정:**

1. [pandoc.org/installing](https://pandoc.org/installing.html)에서 Pandoc을 설치하거나 패키지 관리자를 통해 설치합니다:
   - macOS: `brew install pandoc`
   - Windows: `winget install pandoc`
   - Linux: `apt install pandoc`
2. VMark를 재시작하거나 **설정 → 파일 및 이미지 → 문서 도구** 로 이동하여 **감지** 클릭
3. **파일 → 내보내기 → Pandoc 사용 → [형식]** 을 사용하여 내보내기

Pandoc이 설치되어 있지 않으면 **Pandoc 사용** 하위 메뉴에 항목이 하나만 표시됩니다 — **"Pandoc을 설치하여 Word, EPUB, LaTeX… 내보내기"** — 클릭하면 Pandoc 설치 안내가 열립니다.

**설정 → 파일 및 이미지 → 문서 도구** 에서 Pandoc이 감지되었는지 확인할 수 있습니다.

### HTML로 복사

`Cmd/Ctrl + Shift + C`를 눌러 렌더링된 문서를 HTML **소스**로 복사합니다. 마크업은 스타일 없이 일반 텍스트로 클립보드에 들어가므로, HTML 코드를 넣는 곳 — CMS의 HTML 보기, 템플릿, 코드 편집기 — 에 붙여넣으세요. Word나 Mail 같은 서식 있는 텍스트 편집기에서는 태그가 그대로 표시됩니다. 로컬 이미지는 데이터 URI로 포함되므로 HTML이 VMark 밖으로 나가도 계속 표시됩니다.

## VMark Reader

모든 HTML 내보내기에는 **VMark Reader** — 자체 설정, 탐색, 라이트박스를 갖춘 대화형 독서 경험 — 가 포함됩니다.

### 설정 패널

기어 아이콘 (오른쪽 하단)을 클릭하면 설정 패널이 열리고, `Esc`로 다시 닫습니다. 선택한 설정은 브라우저(`localStorage`)가 기억하므로 다음에 파일을 열 때도 적용됩니다.

| 설정 | 옵션 |
|------|------|
| 글꼴 크기 | 12px – 28px |
| 줄 높이 | 1.2 – 2.4 |
| 콘텐츠 너비 | 30em – 80em |
| 라틴 글꼴 | System, Athelas, Palatino, Georgia, Charter, Literata |
| CJK 글꼴 | System, PingFang, Songti, Kaiti, Noto Serif, Source Han |
| 테마 | White, Paper (기본값), Mint, Sepia, Night |
| CJK 자간 | 0.02em – 0.12em |
| CJK-라틴 간격 | CJK와 라틴 문자 사이 자동 간격 토글 |
| 목차 | TOC 사이드바 토글 (`T`를 누르는 것과 동일) |
| 모든 섹션 펼치기 | 접을 수 있는 모든 `<details>` 블록 열기 |
| 기본값으로 재설정 | 모든 설정을 원래대로 되돌리기 |

### 목차

TOC 사이드바는 긴 문서 탐색을 돕습니다:

- **토글**: 페이지 가장자리의 탭을 클릭하거나 `T` 누르기
- **탐색**: 제목을 클릭하여 이동
- **하이라이트**: 스크롤 시 현재 섹션이 강조 표시됨

### 읽기 진행 상황

페이지 상단의 미묘한 진행 막대가 문서를 얼마나 읽었는지 보여줍니다.

### 맨 위로

스크롤을 내리면 플로팅 버튼이 나타납니다. 클릭하면 맨 위로 돌아갑니다.

### 이미지 라이트박스

이미지를 클릭하면 전체 화면 라이트박스에서 볼 수 있습니다:

- **닫기**: 바깥쪽 클릭, `Esc` 누르기, 또는 X 버튼 클릭
- **줌**: 이미지가 원래 크기로 표시됨

### 코드 블록

각 코드 블록에는 대화형 컨트롤이 포함됩니다:

| 버튼 | 기능 |
|------|------|
| 줄 번호 토글 | 이 블록의 줄 번호 표시/숨기기 |
| 복사 버튼 | 코드를 클립보드에 복사 |

복사 버튼은 성공 시 체크 표시를 표시합니다.

### 각주 탐색

각주는 완전히 대화형입니다:

- 각주 참조 `[1]`을 클릭하면 정의로 이동
- `↩` 역참조를 클릭하면 읽던 위치로 돌아감

### 키보드 단축키

| 키 | 동작 |
|----|------|
| `Esc` | 설정 패널 또는 라이트박스 닫기 |
| `T` | 목차 토글 |
| `+` / `=` | 글꼴 크기 키우기 |
| `-` | 글꼴 크기 줄이기 |

## 팁

### 내보낸 HTML 서비스하기

폴더 내보내기 구조는 모든 정적 파일 서버와 잘 작동합니다:

```bash
# Python
cd MyDocument && python -m http.server 8000

# Node.js (npx)
npx serve MyDocument

# 직접 열기
open MyDocument/index.html
```

### 오프라인 보기

두 파일 모두 오프라인에서 열리지만, 수식이 포함된 문서에서는 한 가지 차이가 있습니다:

- **`standalone.html`** 은 완전히 자체 완결적입니다 — KaTeX 스타일시트와 폰트가 내보낼 때 인라인으로 포함되므로 연결 없이도 수식이 렌더링됩니다.
- **`index.html`** 은 CDN(jsDelivr)에서 KaTeX 스타일시트를 불러오므로, 페이지를 열 때 수식에 인터넷 연결이 필요합니다. Reader, 이미지, `assets/` 아래의 폰트는 로컬입니다.

폰트는 내보내는 동안 다운로드됩니다. 문서에 수식이 있으면 KaTeX 폰트를, 라틴 폰트와 고정폭 폰트가 VMark가 아는 웹 폰트(Literata, JetBrains Mono, Fira Code, IBM Plex Mono)이면 그 폰트를 받습니다. CJK 폰트 설정은 포함되지 않으며, 시스템 폰트나 사용자 지정 폰트 패밀리도 포함되지 않습니다 — 이런 폰트는 내보낸 페이지가 읽는 사람의 시스템 폰트 스택을 씁니다. 폰트를 포함하려면 인터넷에 연결된 컴퓨터에서 내보내세요 — 오프라인 내보내기는 시스템 폰트로 대체됩니다.

### 포함되는 이미지

내보낸 파일에는 실제 이미지 바이트가 담기고 내보낸 파일은 공유되기 마련입니다 —
그래서 VMark는 그 바이트를 가져올 수 있는 위치를 제한합니다:

| 문서가… | 이미지를 가져올 수 있는 위치 |
|---|---|
| 열린 워크스페이스 안에 있음 | 그 워크스페이스 안 어디든 |
| 단독으로 열림 | 문서 자신의 폴더와 그 하위 |
| 저장되지 않음 (디스크에 한 번도 저장하지 않음) | 어디에서도 안 됨 — 워크스페이스가 열려 있어도 로컬 이미지는 포함되지 않습니다. 원격 이미지는 영향을 받지 않습니다 |

저장되지 않은 문서는 먼저 저장한 뒤 다시 내보내세요. HTML, 인쇄, PDF, HTML로 복사 모두에 해당합니다.

상대 경로는 에디터에서와 똑같이 문서의 폴더를 기준으로 해석됩니다 — 따라서
`../images/photo.png`는 대상이 위 경계 안에 있는 한 작동합니다. 경계 밖의 모든 것
(`~/.ssh/id_rsa`, `/etc/passwd`, 디스크의 다른 곳을 가리키는 절대 경로)은 거부되어
"Image not found" 자리 표시자로 내보내지며, 내보내기 경고에 집계됩니다.

`../` 이미지가 자리 표시자로 내보내진다면, 해당 폴더를 워크스페이스로 열고 다시
내보내세요.

### 모범 사례

1. 게시할 문서는 **`index.html`을 호스팅** 하세요 — 옆에 `assets/` 폴더를 함께 두세요
2. 이메일이나 채팅으로 빠르게 공유할 때는 **`standalone.html`을 보내세요**
3. **접근성을 위해 설명적인 이미지 대체 텍스트** 포함
4. **다양한 브라우저에서 내보낸 HTML 테스트**
