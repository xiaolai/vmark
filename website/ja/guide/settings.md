# 設定

VMark の設定パネルではエディタのすべての側面をカスタマイズできます。`Mod + ,` を押すか、メニューバーの **VMark > 設定** で開きます。

設定ウィンドウのサイドバーには、セクションがアルファベット順（英語名による）に並び、About が末尾に、表示されている場合は詳細設定がその下に表示されます。変更はすぐに反映されます——保存ボタンはありません。

サイドバー上部の**検索ボックス**を使うと、すべてのパネルの設定を名前や説明で絞り込めます——一致した行がまとめて表示されるため、設定がどのカテゴリにあるかを知っている必要はありません。すべてを工場出荷時のデフォルトに戻すには、About セクションの **デフォルトにリセット** を使います。

## 外観

視覚的なテーマとウィンドウの動作を制御します。

### テーマ

6 つのカラーテーマから選択します。アクティブなテーマはスウォッチの周りのリングで示されます。

| テーマ | 背景 | スタイル |
|-------|-----|--------|
| White | `#FFFFFF` | クリーンな白、最高のコントラスト |
| Paper | `#EEEDED` | 温かみのある新聞用紙の色（デフォルト） |
| Mint | `#CCE6D0` | ソフトグリーン、目に優しい |
| Sepia | `#F9F0DB` | 書籍用紙の色、長時間の読書向け |
| Night | `#23262B` | 暗い場所向けのダークスレート |
| Solarized | `#002B36` | Solarized Dark、定番のパレット |

::: info Windows 10 と Linux では White と Night のみ
Windows 10 と Linux ではタイトルバーをシステムが描画し、それはライトかダークのどちらかにしかできません。そのためこれらのプラットフォームでは **White** と **Night** のみが選択でき、システムのウィンドウ枠と合わせられないテーマは 2 つのうち近い方で表示されます：Paper、Mint、Sepia は White として、Solarized は Night として表示されます。保存された選択は変更されません——macOS と Windows 11 ではすべてのテーマを利用できます。Windows 11 ではタイトルバーがテーマ自身の色になりますが、メニューバーは引き続きライトかダークで描画されます。
:::

#### システムの外観に合わせる

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| システムの外観に合わせる | システムに合わせてライトテーマとダークテーマを自動的に切り替えます | オフ |

有効にすると、1 行だったテーマの行が 2 行に置き換わります——**ライトテーマ**（システムがライトモードのときに使用、デフォルトは Paper）と **ダークテーマ**（ダークモードで使用、デフォルトは Night）です。VMark はシステムの外観が変わった瞬間にこれらを切り替えます。手動で選んだテーマは保持され、このオプションをオフにすると元に戻ります。

### サイドバー

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| サイドバーのスタイル | サイドバーとワークスペースレールの枠の表示方法。**全高**は macOS 標準のサイドバーと同様に、細い区切り線とともにウィンドウの端に沿って配置します。**カード**は角丸と影付きでウィンドウ内に浮かせて表示します。設定ウィンドウにも適用されます | 全高 | 全高、カード |

### ウィンドウ

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| タイトルバーにファイル名を表示 | macOS ウィンドウのタイトルバーに現在のファイル名を表示。**macOS のみ**——Windows と Linux では常にシステムのタイトルバーにファイル名が表示されるため、それ以外ではこの設定は非表示です | オフ |

macOS では、VMark がシステムのタイトルバーの上に独自のタイトルバーを描画するため、ファイル名はその帯に任意で表示する要素です。Windows と Linux では、システムがウィンドウの上に本物のタイトルバーを描画します。ファイル名（未保存の変更がある間は `•` 付き）は常にそこに表示され、VMark は独自のタイトル帯を追加しません。

### フォーカスモード

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| 減光レベル | フォーカスモードで、フォーカスされていないコンテンツをどれだけ強く減光するか。**標準** はデフォルトの色だけによる減光を維持し、**強** と **より強** はその上に段階的に低い不透明度を加えます | 標準 | 標準、強、より強 |

## エディタ

タイポグラフィ、表示、編集動作、空白、大きなファイルの設定。

### タイポグラフィ

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| ラテンフォント | ラテン（英語）テキストのフォントファミリー | システムデフォルト | System Default、Athelas、Palatino、Georgia、Charter、Literata——およびインストール済みの任意のフォント |
| CJK フォント | 中国語、日本語、韓国語テキストのフォントファミリー | システムデフォルト | System Default、PingFang SC、Songti SC、Kaiti SC、Noto Serif CJK、Source Han Sans——およびインストール済みの任意のフォント |
| モノフォント | コードとモノスペーステキストのフォントファミリー——統合ターミナルでも使用されます | システムデフォルト | System Default、SF Mono、Monaco、Menlo、Consolas、DejaVu Sans Mono、Liberation Mono、Ubuntu Mono、Noto Sans Mono、Noto Sans Mono CJK SC、JetBrains Mono、Fira Code、SauceCodePro NFM、IBM Plex Mono、Hack、Inconsolata——およびインストール済みの任意のフォント |
| フォントサイズ | エディタコンテンツの基本フォントサイズ | 18px | 14px、16px、18px、20px、22px |
| 行の高さ | 行間の縦方向の間隔 | 1.8（Relaxed） | 1.4（Compact）、1.6（Normal）、1.8（Relaxed）、2.0（Spacious）、2.2（Extra） |
| ブロック間隔 | 行の高さの倍数で測定されたブロック要素（見出し、段落、リスト）間の視覚的なギャップ | 1x（Normal） | 0.5x（Tight）、1x（Normal）、1.5x（Relaxed）、2x（Spacious） |
| CJK 文字間隔 | CJK 文字間の追加の間隔（em 単位） | Off | Off、0.02em（Subtle）、0.03em（Light）、0.05em（Normal）、0.08em（Wide）、0.10em（Wider）、0.12em（Extra） |

#### 自分でインストールしたフォントを使う

上に挙げた名前は候補の一覧であり、上限ではありません。3 つのフォントピッカーにはそれぞれ、マシン上のすべてのフォントファミリーを一覧表示する **インストール済みフォント** セクションもあるため、自分でインストールした書体——LXGW WenKai、Iosevka、Source Han Serif——も組み込みのものと同じ方法で選べます。

代わりにファミリー名を入力するには、リストの末尾にある **カスタム…** を選びます。システムが報告するとおりの名前をそのまま使ってください（macOS：Font Book、Windows：設定 → 個人用設定 → フォント）——LXGW WenKai / 霞鹜文楷 の場合は `LXGW WenKai` です。フォントは名前を入力し終えるとすぐに適用されます。何も変わらない場合は、その名前がインストール済みのファミリーと一致していません。引用符、カンマ、セミコロン、括弧を含む名前は拒否され、行にその旨が表示されます。

::: tip インストール済みフォントは macOS のみ
macOS では、インストールされているすべてのファミリーが一覧表示されます。Windows と Linux ではこのセクションは空なので、**カスタム…** から入力します——ファミリー名の入力は 3 つのプラットフォームすべてで同じように機能します。
:::

この選択は PDF エクスポートにも引き継がれます。PDF エクスポートは同じエンジンで同じフォントを使って描画されるからです。HTML エクスポートはマシン上のフォントを同梱できないため、エクスポートしたページは、閲覧者が同じファミリーをインストールしていない限り、閲覧者自身のフォントにフォールバックします。

### 表示

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| エディタ幅 | コンテンツの最大幅。広い値は大型モニターに適し、狭い値は可読性を向上させます | 50em（Medium） | 36em（Compact）、42em（Narrow）、50em（Medium）、60em（Wide）、80em（Extra Wide）、Unlimited |

::: tip 同じ幅でも、ラテン文字と CJK では読み心地が異なります
エディタ幅は `em` で測られるため、*文字数*で見た行の長さは文字体系によって変わります。50em では、ラテン文字の行はおよそ 90〜100 文字（タイポグラファーが推奨する 45〜75 文字の約 2 倍で、2 ペインのエディタに適しています）になる一方、CJK の行は全角でおよそ 50 文字——中国語の文章で伝統的な 40〜60 文字の範囲にちょうど収まります。主にラテン文字の散文を書いていて書籍のような行長にしたい場合は 36〜42em を選んでください。主に CJK のドキュメントでは、デフォルトがすでに古典的な行長です。
:::

::: tip
18px フォントサイズでの 50em はおよそ 900px——ほとんどのディスプレイで快適な読書幅です。
:::

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| タブサイズ | Tab キーを押したときに挿入されるスペースの数 | 2 スペース | 2 スペース、4 スペース |
| ファイルを新しいタブで開く | 現在の空のタブを再利用せず、既存のファイルを新しいタブで開く | オフ | オン/オフ |
| 自動ペアリングを有効化 | 開き括弧や引用符を入力したときに対応する閉じ括弧/引用符を自動挿入 | オン | オン/オフ |
| CJK 括弧 | `「」` `【】` `《》` などの CJK 固有の括弧を自動ペアリング。自動ペアリングが有効な場合のみ利用可能 | Auto | Off、Auto |
| カーリー引用符を含む | `“”` と `‘’` を自動ペアリングし、入力したストレートな `"` や `'` をカーリー引用符のペアに変換します。一部の IME のスマート引用符機能と競合する場合があります。CJK 括弧が Auto に設定されているときに表示 | オン | オン/オフ |
| `"` もペアリング | 右ダブル引用符 `"` を入力すると `""` ペアも挿入されます。IME が開き/閉じ引用符を交互に使う場合に便利です。カーリー引用符が有効な場合に表示 | オフ | オン/オフ |
| コピー形式 | WYSIWYG モードからコピーする際のプレーンテキストクリップボードスロットの形式 | プレーンテキスト | プレーンテキスト、Markdown |
| 選択時にコピー | テキストを選択するたびに自動的にクリップボードにコピー | オフ | オン/オフ |

### 空白

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| 保存時の行末 | ファイル保存時の行末の処理方法 | 既存を保持 | 既存を保持、LF（`\n`）、CRLF（`\r\n`） |
| 改行をハードブレークにする | 段落内の単一の改行をハードブレークとして扱う（ブロック間の空行には影響しません） | オフ | オン/オフ |
| 連続した改行を保持 | 複数の空白行を折りたたまずにそのまま保持 | オン | オン/オフ |
| 保存時のハードブレークスタイル | 保存された Markdown ファイルでのハードな改行の表現方法 | 既存を保持 | 2 スペース（推奨）、既存を保持、バックスラッシュ（`\`） |
| `<br>` タグを表示 | エディタで HTML の改行タグを見えるように表示 | オフ | オン/オフ |
| 不可視文字を表示 | 空白を可視化します：スペースは `·`、タブは `→`（ソースのみ）、ソフト改行は `↓`（ソースのみ）、ハード改行は `⏎`。印刷時は非表示。切り替え：`F3` または 表示 → 不可視文字を表示 | オフ | オン/オフ |

::: tip
2 スペースは最も互換性の高いハードブレークスタイルです——GitHub、GitLab、すべての主要な Markdown レンダラーで動作します。バックスラッシュスタイルは Reddit、Jekyll、一部の古いパーサーで失敗することがあります。
:::

### 大きなファイル

|-----|-----|---------|--------|
| 自動ソースモード | 大きなファイルをソースモードで開く — 1 MB を超えるファイル、または推定 1,200 ブロック以上の Markdown（WYSIWYG をスキップしてパフォーマンスを保つ）。ステータスバーからいつでも WYSIWYG に切り替えられます | オン | オン/オフ |

## Markdown

貼り付け動作、レイアウト、HTML レンダリング設定。

### 貼り付けと入力

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| 検索で正規表現を有効化 | 検索と置換バーに正規表現切り替えボタンを表示 | オン | オン/オフ |
| 貼り付けモード | 貼り付け時にクリップボードのコンテンツをどう処理するか。**スマート** は HTML を Markdown に変換し Markdown 構文を検出します。**プレーンテキスト** は常にプレーンテキストとして貼り付けます。**リッチ** は元の HTML の書式を保持します | スマート | スマート、プレーンテキスト、リッチ |
| WYSIWYG での Markdown 貼り付け | WYSIWYG エディタに Markdown のように見えるテキストを貼り付けると、自動的にリッチコンテンツに変換 | Auto | Auto、オフ |

### レイアウト

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| デフォルトでソース/プレビューを分割 | Markdown ファイルを、ソースとライブプレビューを並べた分割表示で開く（オフの場合は WYSIWYG）。セッションごとの切り替えは `Shift + F6` または **表示 → Markdown分割ビュー** | オフ | オン/オフ |
| ブロック要素フォントサイズ | リスト、引用ブロック、テーブル、アラート、details ブロックの相対フォントサイズ | 100% | 100%、95%、90%、85% |
| 見出しの整列 | 見出しのテキスト整列。エディタ内のみで、エクスポートや印刷には適用されません | 左 | 左、中央 |
| 画像とダイアグラムの境界線 | 画像、Mermaid ダイアグラム、数式ブロックの周りに境界線を表示するか。エディタ内のみで、エクスポートや印刷には適用されません | なし | なし、常に、ホバー時 |
| 画像とテーブルの整列 | ブロック画像とテーブルの水平方向の整列。エディタ内のみで、エクスポートや印刷には適用されません | 中央 | 中央、左 |
| テーブルを幅に合わせる | 横スクロールを許可せず、すべてのテーブルをエディタの幅に収める | オフ | オン/オフ |
| コードブロックの行番号 | WYSIWYG エディタでコードブロック内に行番号を表示。ソース／分割エディタのガターを制御する表示メニューの **行番号** とは独立しています | オフ | オン/オフ |

### Lint

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| Markdown Lint を有効化 | 一般的な Markdown の問題をチェック（壊れたリンク、alt テキストの欠落、見出しレベルの飛び、閉じられていないフェンスなど） | オン | オン/オフ |

完全なルールリストと重要度レベルは [Markdown Lint](/ja/guide/lint) を参照してください。

### HTML レンダリング

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| リッチテキストでの生 HTML | WYSIWYG モードで生 HTML ブロックをレンダリングするかどうか | サニタイズ | 非表示、サニタイズ、サニタイズ + スタイル |
| 許可する HTML タグ | レンダリングするタグの範囲の広さ | 厳格 | 厳格、拡張 |
| 追加で許可するタグ | 追加で許可するタグ名（カンマ区切り） | _（空）_ | 例：`kbd, samp, var` |

::: tip
**非表示** は生 HTML を折りたたみ、何もレンダリングしません。**サニタイズ** は危険なタグを除去して HTML をレンダリングします。**サニタイズ + スタイル** はさらに、インラインの `style` 属性のうち安全なサブセットも保持します。

**厳格** は小さく保守的なタグセットを許可します。**拡張** はさらに `<svg>`（とその安全な子要素）、`<figure>`/`<figcaption>`、`<details>`/`<summary>`、その他のセマンティック／構造的なタグもレンダリングします——いずれも引き続きサニタイズされます。特定のタグをさらに追加するには **追加で許可するタグ** を使います（例：`kbd, samp, var`）。
:::

::: warning
これらの設定にかかわらず、危険なタグ（`<script>`、`<style>`、`<iframe>`、`<form>`、イベントハンドラーなど）は**常に**除去されます——カスタムタグの欄でそれらを再び有効にすることはできません。許可リストの広さが影響するのは WYSIWYG のプレビューだけで、ファイル内の生 HTML が変更されることはありません。
:::

## ファイルと画像

ファイルブラウザー、保存、ドキュメント履歴、画像処理、ドキュメントツール。

### ワークスペース

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| ワークスペースレール | 左側にワークスペースレールを表示し、複数のワークスペースと単独のファイルを 1 つのウィンドウにまとめる | オフ |

レールで何ができるかは [ワークスペースレール](/ja/guide/workspace-rail) を参照してください。

### ファイルブラウザー

最初の 2 つの設定はワークスペース（フォルダー）が開いている場合のみ適用され、ワークスペースごとに保存されます。

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| 隠しファイルを表示 | ファイルエクスプローラーのサイドバーにドットファイルと隠しシステム項目を表示 | オフ |
| すべてのファイルを表示 | ファイルエクスプローラーに非 markdown ファイルを表示。非 markdown ファイルはシステムのデフォルトアプリケーションで開かれます | オフ |
| 拡張子を表示 | サイドバー、タブストリップ、タイトルバーに完全なファイル名——`notes` ではなく `notes.md`——を表示。ワークスペースの有無にかかわらず、あらゆる場所に適用されます | オン |

**拡張子を表示** をオフにしても、隠れるのは VMark が認識する拡張子だけです。VMark が開けないファイルはどちらの場合も拡張子が付いたままなので、表示される名前は常にディスク上に実在します。

### 終了動作

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| 終了の確認 | 誤って終了しないように `Cmd+Q`（または `Ctrl+Q`）を 2 回押す必要があるようにする | オン |
| 閉じるときにトレイに最小化 | **Windows のみ。** 最後のウィンドウを閉じても、終了せずに VMark をシステムトレイで実行し続ける | オフ |

**閉じるときにトレイに最小化** が変えるのは*最後の*ウィンドウだけです。複数のウィンドウが開いている場合、1 つを閉じればそのウィンドウは閉じます。以前なら VMark を終了させていた最後の「閉じる」だけが、代わりに VMark をトレイに待機させます。何も閉じられないため、未保存の作業はそのままの場所に残ります。

- トレイアイコンを**左クリック**すると VMark が戻ります。
- **右クリック**すると **VMark を表示** と **VMark を終了** が表示されます。トレイから終了すると、まずウィンドウが戻るため、未保存の変更に関する確認が表示されたときに応答できます。
- `Ctrl+Q` は通常どおり終了します。
- VMark がトレイにある間にこの設定をオフにすると、アイコンが消える前にウィンドウが戻るため、ウィンドウもアイコンもないまま VMark が実行され続けることはありません。

この設定は macOS と Linux には表示されません。

### 保存

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| 自動保存を有効化 | 編集後にファイルを自動的に保存 | オン | オン/オフ |

| 保存間隔 | 自動保存の間隔。自動保存が有効な場合のみ利用可能 | 30 秒 | 10 秒、30 秒、1 分、2 分、5 分 |

## 統合

MCP サーバーと AI プロバイダーの設定。

### MCP サーバー

MCP（Model Context Protocol）サーバーにより、Claude Code や Cursor などの外部 AI アシスタントが VMark をプログラムで制御できます。

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| MCP サーバーを有効化 | MCP サーバーを開始または停止します。実行中、ステータスバッジにポートと接続されているクライアントが表示されます | オン（切り替え） |
| 起動時に開始 | VMark 起動時に MCP サーバーを自動起動 | オン |
| 新しい場所への保存とジーニーの結果を自動承認 | MCP クライアントが確認なしにドキュメントを新しい場所へ保存できるようにし、ジーニーがプレビューを表示せずに結果を直接適用できるようにします。オフの場合、新しいパスへ保存する MCP リクエストは拒否され、トーストで通知されます。MCP によるドキュメントの書き込みはこの設定に左右されません——書き込みごとにエージェントの編集履歴に記録され、ステータスバーの MCP 書き込み履歴から復元できます | オフ |

サーバーが実行中の場合、パネルには以下も表示されます：
- **ポート**——自動割り当て。AI クライアントは設定ファイルを通じて検出します
- **バージョン**——MCP サーバーサイドカーのバージョン
- **ツール/リソース**——利用可能な MCP ツールとリソースの数
- **接続クライアント**——現在接続している AI クライアントの数

MCP サーバーセクションの下で、サポートされている AI クライアント（Claude Desktop、Claude Code、Codex CLI、Gemini CLI）に VMark の MCP 設定をワンクリックでインストールできます。

詳細は[MCP セットアップ](/ja/guide/mcp-setup)と[MCP ツールリファレンス](/ja/guide/mcp-tools)を参照してください。

### AI プロバイダー

[AI Genie](/ja/guide/ai-genies)を動かす AI プロバイダーを設定します。一度にアクティブにできるプロバイダーは 1 つだけです。

**CLI プロバイダー**——ローカルにインストールされた AI CLI ツール（Claude、Codex、Gemini）を使用します。**検出** をクリックして `$PATH` で利用可能な CLI をスキャンします。CLI プロバイダーはサブスクリプションプランを使用し、API キーは不要です。

**REST API プロバイダー**——API に直接接続します：Anthropic、OpenAI、**OpenAI 互換**サービス（DeepSeek、Groq、OpenRouter など）、Google AI、またはローカルの Ollama サーバー（Ollama API）。いずれもモデル名と API キーが必要です——ただし Ollama では API キーは任意です。Google AI 以外はエンドポイントも指定でき、標準のエンドポイントがあるプロバイダーでは入力済みです（OpenAI 互換スロットには標準がないため、自分で入力します）。

各プロバイダーの詳細なセットアップ手順は[AI プロバイダー](/ja/guide/ai-providers)を参照してください。

## フォーマット

デフォルト以外のフォーマットアダプターのオプトイントグル、および読み取り専用コードタブの外部エディタコマンド。

Markdown、プレーンテキスト、YAML/YML は**常に**登録されています——安定したデフォルトです。その他のアダプターはすべて**デフォルトでオフ**のため、既存のユーザーはアップグレード時に驚きません。トグルを切り替えると、レジストリがその場で再構築されます。開いているタブは適切なアダプターで再マウントされ、再起動は不要です。

すべてのフォーマットとそのプレビューの一覧は[サポートされるフォーマット](/ja/guide/formats)を参照してください。

### フォーマットサポート

| トグル | デフォルト | 有効にするもの |
|---|---|---|
| **データフォーマット** | オフ | `.json`、`.jsonl`、`.toml`——分割ペインのソース + ナビゲート可能なツリー。`Cargo.toml`、`package.json`、`pyproject.toml` のスキーマ対応プレビュー。 |
| **ダイアグラム & SVG** | オフ | `.mmd`（Mermaid）と `.svg`——分割ペインのソース + サニタイズされたライブレンダリング。 |
| **HTML プレビュー** | オフ | `.html` と `.htm`——サンドボックス iframe プレビュー（`sandbox=""` 空の許可リスト、DOMPurify、CSP `<meta>`）。セキュリティの正式な承認はまだ保留中で、プレビューにもその旨が表示されます——[HTML のセキュリティモデル](/ja/guide/formats#html-のセキュリティモデル)を参照。 |
| **コードビューア** | オフ | 12 種類の読み取り専用ビューア（`.ts`、`.tsx`、`.js`、`.jsx`、`.py`、`.rs`、`.go`、`.css`、`.sh`、`.bash`、`.rb`、`.lua`）。シンタックスハイライト付きビューアで開き、**編集を有効化**と**外部エディタで開く**ボタンを提供。 |

カテゴリがオフの場合、対応する拡張子はプレーンテキストのフォールバックに移行するため、ファイルはスキーマビューなしでも引き続き開けます。

### デフォルトの表示モード

プレビューに対応したファイル（HTML、SVG、Mermaid、JSON、YAML、TOML）は、3 つの[表示モード](/ja/guide/formats#表示モード-ソース-分割-プレビュー)のいずれかで開きます：

| オプション | 結果 |
|---|---|
| **ソース** | 編集可能なソースペインを全幅で表示。 |
| **分割**（デフォルト） | ソースとプレビューを並べて表示。 |
| **プレビュー** | 読み取り専用の描画を全幅で表示。 |

これは新しく開いたタブのデフォルトです。各タブは自分の選択を記憶し、画面上の切り替えまたは `F6` / `Shift + F6` でどのタブも切り替えられます。

### 外部エディタ

読み取り専用コードタブの**外部エディタで開く**ボタン用に、起動するエディタを選択します：既知のエディタの名前（`code`、`zed`、`subl`、`vim`、…）か、アプリバンドル（例：`/Applications/Visual Studio Code.app`）または実行ファイルのフルパスです。シェル、インタープリター、ターミナルエミュレーターは拒否され、存在しないパスも拒否されます。

GUI 設定は環境変数より優先されます——明示的なものが暗黙的なものに勝ちます。フィールドを空にすると、環境変数のフォールバックチェーン `$VMARK_EXTERNAL_EDITOR → $VISUAL → $EDITOR → プラットフォームデフォルト` を使用します。完全な解決順序とセキュリティゲートは[外部エディタで開く](/ja/guide/formats#外部エディタで開く)を参照してください。

### アップグレード時の通知

マルチフォーマットサポートへのアップグレード後の最初の起動時、VMark は**設定 → 形式**を指す非ブロッキングトーストを表示します。このお知らせはインストールごとに 1 回だけ表示されます——一度表示（または閉じた）後は再表示されません。

### ファイルタイプの上書き

カテゴリのトグルに加えて、コマンドパレットから個々のファイルファミリーの開き方を上書きできます——**ファイル形式を設定：プレーンテキスト / Markdown / デフォルトに戻す**。上書きはファイルファミリーごと（拡張子ごと、または `.env` のようなファイルではドットファイルの名前ごと）に保存され、セッションをまたいで保持されます。[VMark がファイルの種類を決める仕組み](/ja/guide/formats#vmark-がファイルの種類を決める仕組み)を参照してください。

**形式** パネルには、設定したすべての上書きが `key → format` の形で一覧表示されます。個々のエントリは `×` ボタンで削除でき、**すべて消去** を使うと一度にすべて削除できます——削除したエントリは組み込みのルールに戻ります。

## ショートカット

すべてのキーボードショートカットを表示してカスタマイズします。ショートカットはカテゴリ別（ファイル、編集、表示、フォーマットなど）にグループ化されます。

- **検索**——名前、カテゴリ、またはキーの組み合わせでショートカットをフィルタリング
- **ショートカットをクリック** してキーバインドを変更します。新しいキーの組み合わせを押して確認
- **リセット**——個々のショートカットをデフォルトに戻すか、すべてを一度にリセット
- **エクスポート/インポート**——カスタムバインドを JSON ファイルとして保存し、別のマシンでインポート

デフォルトのショートカットリファレンスは[キーボードショートカット](/ja/guide/shortcuts)を参照してください。

プラットフォーム固有の切り替えが 2 つあり、どちらもデフォルトでオンです：**OptionをMetaキーとして使用**（macOS のみ——Option キーを Meta として扱います。emacs や tmux が `Alt` プレフィックスのショートカットや単語移動に期待する動作です。`Option + E` のような Option のデッドキーでアクセント記号を入力する場合はオフにしてください）と **シェル統合**（Windows では非表示——zsh と bash にコマンドマーカーを注入し、プロンプトナビゲーション、終了ステータスの表示、カレントディレクトリの追跡を可能にします。新しいターミナルセッションから有効になります）。

## About

アプリのバージョン、Web サイトとレポジトリへのリンク、アップデート管理が表示されます。**サードパーティ通知** リンクは、VMark に同梱されているオープンソースソフトウェアのライセンス文を、テキストファイル用のシステム既定のアプリで開きます。

### アップデート

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| 自動アップデート | 定期的に新しいバージョンを確認する | オン | オン/オフ |
| 確認頻度 | アップデートを確認する頻度。自動アップデートがオンの場合のみ利用可能 | 起動時 | 起動時、毎日、毎週、手動のみ |
| アップデートを自動的にダウンロード | 利用可能になったときに新しいバージョンをバックグラウンドでダウンロードする | オフ | オン/オフ |
| 今すぐ確認 | 手動でアップデートチェックをトリガー | — | — |

アップデートが利用可能な場合、新しいバージョン番号、リリース日、リリースノートを示すカードが表示されます。アップデートを **ダウンロード**、このバージョンを **スキップ**、またはダウンロード後に **再起動してアップデート** できます。

#### アップデートは VMark のインストール方法に合わせて行われます

アップデーターは、プラットフォームごとに固定された形式ではなく、インストールしたのと同じパッケージ形式をダウンロードします：

| インストールしたもの | アップデーターが取得するもの |
|---|---|
| macOS `.dmg` | 署名済みのアプリバンドル |
| Windows `.exe`（NSIS） | `.exe` インストーラー |
| Windows `.msi` | `.msi` パッケージ |
| Linux `.deb` | `.deb` パッケージ |
| Linux `.rpm` | `.rpm` パッケージ |
| Linux AppImage | AppImage |

Linux で `.deb` や `.rpm` のインストールを更新するとシステムのパッケージマネージャーが実行されるため、認証を求められます——システムパッケージのインストールには root 権限が必要です。AppImage の更新はファイルをその場で置き換えるため、確認は不要です。

#### アップデートが止まってしまった場合

確認もダウンロードもネットワークを経由します。接続がきっぱり失敗するのではなくハングしてしまうと、アップデートが永遠に進行中のままになりかねません。確認が 1 分間、またはダウンロードやインストールが 3 分間進まない場合、VMark はドキュメントウィンドウに消えない **アップデートが停止しました** 通知を表示します。その **再試行** ボタンを押すとアップデーターが待機状態に戻るので、もう一度試せます——このセクションの **今すぐ確認**、または次の自動確認で、新しい確認からやり直します。

アップデートの動作はログファイルに書き込まれるため、問題が繰り返す場合はログをバグ報告に添付する価値があります：

| プラットフォーム | ログの場所 |
|---|---|
| macOS | `~/Library/Logs/app.vmark/` |
| Windows | `%LOCALAPPDATA%\app.vmark\logs\` |
| Linux | `~/.local/share/app.vmark/logs/` |

### リセット

| 設定 | 説明 |
|-----|-----|
| デフォルトにリセット | これらのペインの設定をデフォルト値に戻します。先に確認プロンプトが表示されます——この操作は取り消せません |

次の 3 つは別に保存されており、リセット**されません**：キーボードショートカットのカスタマイズ（[ショートカット](#ショートカット)ペインの **すべてリセット** を使います）、AI プロバイダーの設定、ワークスペースごとのファイルブラウザー設定（**隠しファイルを表示**、**すべてのファイルを表示**）。インターフェース言語はシステムの言語に戻ります。

## 詳細設定

::: tip
詳細設定セクションはデフォルトで表示されています——デフォルトでオンになっている埋め込みブラウザのオフスイッチがここにあるためです。設定ウィンドウで `Ctrl + Option + Cmd + D` を押すと非表示になり、もう一度押すと再び表示されます。
:::

開発者およびシステムレベルの設定。

### リンクプロトコル

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| カスタムリンクプロトコル | VMark がリンクとして扱う追加の URL プロトコル。各プロトコルをタグとして入力 | `obsidian`、`vscode`、`dict`、`x-dictionary` |

このリストには 2 つの役割があります。リンクを挿入するとき、これらのプロトコルを持つクリップボードの URL は `https://` と同じようにリンクとして認識されます。そしてリンクを開くとき、VMark はプロトコルが `http`、`https`、`mailto`、またはこのリストにある場合にのみシステムへ渡します——そのため `obsidian://open?vault=...` や `vscode://file/...` のリンクはそれぞれのアプリで開き、それ以外のプロトコルは拒否されます。`javascript:`、`data:`、`file:` などいくつかのプロトコルは、リストの内容にかかわらず決して有効にできません。

削除したデフォルトは削除されたままになります。新しいバージョンの VMark で追加されたデフォルトのプロトコルは、そのバージョンを初めて起動したときに一度だけリストに追加されます。

### パフォーマンス

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| 両方のエディタを起動したまま保持 | WYSIWYG モードとソースモードのエディタを同時にマウントして、モード切り替えを高速化します。メモリ使用量が増加します | オフ |

### 整合性

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| 意味チェックの確信度 | チェックの回答が判定として記録されるために必要な確信の度合い。これを下回る回答は保持されますが、不明として扱われます | 0.9 | 0.7、0.8、0.9、0.95 |

チェックとは何か、判定がどのように記録されるかは [整合性](/ja/guide/coherence) を参照してください。

### ワークフローファイル

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| アクションのメタデータを取得 | 参照されている GitHub Actions から `action.yml` を取得し、構造化エディタの `with:` フォームを埋めることを VMark に許可します。ワークフローエディタを完全にオフラインに保つにはオフにしてください | オン | オン/オフ |
| actionlint が利用可能なら使用 | PATH 上に `actionlint` バイナリがある場合、ワークフローファイルに対して実行してより詳しい診断を得ます。バイナリがインストールされていない場合は何もしません | オン | オン/オフ |

### ワークフロー

GitHub Actions ビューアにはオン／オフのスイッチがありません：`.github/workflows/` 配下のファイルを開くとグラフとフォームエディタが表示され、ソースペインの補助機能（式の補完、カーソルとキャンバスの同期、`uses:` の定義へ移動）も一緒に読み込まれます。ここにあるのは、ビューアの設定 1 つと、それとは別の実行エンジンです。

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| 保存時に YAML の書式を保持 | フォームパネル経由で行ったワークフロー編集を保存するとき、CST ラウンドトリップパイプラインを経由して元の YAML のコメント、アンカー、キー順、空行を保持。オフの場合、保存はコンパクトなシリアライザーを使用（高速だが情報が失われる） | オン | オン/オフ |
| ワークフローエンジン | VMark 独自の YAML ワークフローファイルを実行します：ワークフローファイルを開くと、ソースの横にステップグラフと実行／キャンセルのツールバーが表示され、ワークフロー Genie を実行できるようになります。ステップは AI プロバイダーを呼び出したりファイルを書き込んだりできるため、明示的に有効にするまではオフのままです | オフ | オン/オフ |

エンジンはビューアの表示内容を変えません：GitHub Actions のファイルはどちらの場合もビューアで開き、エンジンがオフのとき VMark のワークフローファイルは通常の YAML ツリーとして表示されます。またエンジンがオフの場合、VMark はワークフロー実行のリクエストを、ボタンを隠すだけでなく完全に拒否し（MCP 経由で届くリクエストも含む）、「ワークフローエンジンは設定でオフになっています」と報告します。

どちらの行も **開発者ツール**（下記参照）の下にあり、開発者ツールをオンにすると表示されます。ビューアについては [ワークフロービューア](/ja/guide/workflow-viewer) を、エンジンについては [Genie ワークフロー](/ja/guide/workflows) を参照してください。

### 埋め込みブラウザ

| 設定 | 説明 | デフォルト | オプション |
|-----|-----|---------|--------|
| 埋め込みブラウザ | アプリ内の Web ブラウザ（macOS のみ）。オンの間は、ファイルメニューとコマンドパレットに **新しいブラウザタブ** があり、MCP の `browser` ツールが利用できます。オフにすると、開いているブラウザタブが閉じ、AI による自動操作の窓口が取り下げられます | オン | オン/オフ |
| AI ブラウザセッション | `Sandbox`（推奨。分離された非永続の AI 用 Cookie）または `Shared profile`（移動先の承認を伴う人間のプロファイル）を選択 | サンドボックス | サンドボックス / 共有プロファイル |
| AI のループバックアクセスを許可 | AI が localhost およびループバックアドレスへ移動することを許可します。プライベート LAN、メタデータ、リンクローカルの範囲は引き続きブロックされます | オフ | オン/オフ |

これらは **詳細設定 → macOS** の下にあり、macOS でのみ表示されます。2 つの AI 関連の行はブラウザのトグルがオンの間だけ表示され、トグルがオンになったことによる影響は受けません——変更するまでサンドボックス／ループバックはブロックのままです。機能の全体像は [組み込みブラウザ](/ja/guide/browser) を参照してください。

### プラットフォーム固有

| 設定 | 説明 | デフォルト | プラットフォーム |
|-----|-----|---------|--------------|
| 開く時に macOS 検疫属性をクリア | ワークスペースを開くとき、ワークスペースフォルダーと、その直下にある VMark で開けるファイルから macOS のダウンロード検疫属性（`com.apple.quarantine`）を除去します（サブフォルダーには触れません）。これがないと、VMark の実行中にダウンロードしたファイルを Finder でダブルクリックしても、macOS が黙って無視することがあります。UI では **詳細設定 → macOS** の **ワークスペースを開く際にダウンロードの隔離を解除** として表示されます | オン | macOS |

ターミナルの **OptionをMetaキーとして使用** 設定は [ターミナル](#ターミナル) ペインにあります。

### 開発者ツール

**開発者ツール** は、実験的な設定や開発専用の設定のための、永続化されるマスタースイッチです。オンにすると、**保存時に YAML の書式を保持** の行、**ワークフローエンジン** のトグル、**Hot Exit Dev Tools** パネル（セッションキャプチャ、検査、復元、クリア、再起動のテスト用ボタン）が表示されます。スイッチは永続化されるため、有効にした開発中の機能はセッションをまたいでもリリースビルドでも利用可能なままです——設定を開くたびに開発者ツールを有効にし直す必要はありません。

また、設定の外でも [ナレッジベース](/ja/guide/knowledge-base) が表示されるようになります。**表示 → ナレッジベース** のメニュー項目、パレットコマンド、`Ctrl + Shift + 4` ショートカットは、開発者ツールがオンになるまで非表示です。どのプラットフォームのリリースビルドにも、この機能が必要とするコンテンツサーバーのランタイムが同梱されていないためです。

| 設定 | 説明 | デフォルト |
|-----|-----|---------|
| 開発者ツール | 開発者モードを有効にし、以下の実験的な設定と開発専用の設定を表示する | オフ |
