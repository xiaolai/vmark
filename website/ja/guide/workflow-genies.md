# ワークフロージーニー

**ワークフロージーニー**とは、[ジーニーワークフロー](/ja/guide/workflows)——複数ステップの YAML パイプライン——を `.yml` または `.yaml` ファイルとしてジーニーフォルダに保存したものです。マークダウンジーニーとまったく同じように、ジーニーピッカー（`Mod + Y`）と **編集 → ジーニー** に表示されます。選択すると、単一のプロンプトを送信する代わりに、ワークフローエンジンでパイプライン全体を実行します。

## 必要条件

| 必要条件 | 理由 |
|-------------|-----|
| **設定 → 詳細設定 → 開発者ツール** を有効にしたうえで **ワークフローエンジン** をオン | エンジンはデフォルトでオフです。エンジンがオフでもピッカーにはワークフロージーニーが表示されますが、実行すると「ワークフローエンジンは設定でオフになっています」というエラーで失敗します |
| 開いているワークスペース | `action/save-file` などのアクションステップは、ワークスペースのルートを基準にパスを解決します。ワークスペースがない場合、VMark はトーストを表示し、実行を開始しません |
| 設定済みの [AI プロバイダー](/ja/guide/ai-providers) | ジーニーステップは、マークダウンジーニーと同じアクティブなプロバイダーを呼び出します |

## 作成する

YAML ファイルはジーニーフォルダ（**編集 → ジーニー → ジーニーフォルダを開く**）の下のどこにでも置けます。マークダウンジーニーと同様に、サブフォルダはカテゴリになります。ピッカーはファイル名をジーニーの名前として、YAML の `description`（ない場合は `name`）を 2 行目として表示します。ワークフロージーニーのスコープはドキュメント全体です——実行には対象となる選択範囲がありません——そのため、各ステップは独自の `with: { input: … }` を指定し、呼び出されるマークダウンジーニーはそれをそのまま `{{content}}` プレースホルダーにバインドします。

同梱のサンプル `triage-and-translate.yml` は、すぐに使える出発点です。フォルダにコピーして、シードテキストを置き換えてください。サンプルの場所、YAML スキーマの全体、式、承認、ステップごとのモデルとタイムアウトは、すべて[ジーニーワークフロー](/ja/guide/workflows)に記載されています。ワークフロージーニーの実行自体は通常どおり進み、承認ダイアログも表示されますが、ライブのステップグラフは表示されず、ワークフローパネルからキャンセルすることもできません（実行中はパネルの実行ボタンがエンジン使用中と報告します）。また、パネルにはこの実行に対する「ファイルを復元」もありません。

単一プロンプトのマークダウンジーニー形式については、[AI ジーニー](/ja/guide/ai-genies)も参照してください。
