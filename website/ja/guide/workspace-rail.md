# ワークスペースレール

::: warning 実験的機能
ワークスペースレールは実験的な機能で、**デフォルトではオフ**です。**設定 → ファイルと画像 → ワークスペース → ワークスペースレール** で有効にしてください。レールがオフの場合、VMark はこれまでどおり、1 つのウィンドウに 1 つのワークスペースという形で動作します。
:::

ワークスペースレールを使うと、1 つのウィンドウに**複数のワークスペースを同時に**保持できます。ワークスペースは左端に色付きのグリフが縦に並んだ帯として表示されます。ワークスペースをクリックすると**完全なコンテキスト切り替え**が行われます：エディタのタブ、サイドバーのファイルツリー、分割ペインのレイアウト、サイドバー／アウトラインの状態が、すべてそのワークスペース独自のものに入れ替わります — 単にフィルターを変えるのではなく、ブラウザで Spaces を切り替えるような感覚です。

## 切り替わるもの、残るもの

| 対象 | レールでの切り替え時 |
|---------|------------------|
| エディタのタブストリップ | アクティブなワークスペースのタブ（とブラウザページ）だけを表示 |
| サイドバーのファイルツリー | アクティブなワークスペースをルートとして表示し直し、フォルダーの開閉状態やスクロール位置もワークスペースごとに保持 |
| 分割ペイン | 各ワークスペースが独自の分割レイアウトを記憶 |
| アウトライン | タブごとの折りたたみ／フィルター／スクロールの状態がワークスペースに追従 |
| 次／前のタブ、タブのコンテキストメニュー、クイックオープンの「開いているタブ」 | アクティブなワークスペースに限定 |
| 閉じたタブを再度開く | 閉じたタブはワークスペースごと（に加えて共有のブラウザスコープ 1 つ）に記録され、**ファイル → 閉じたタブを再度開く**、コマンドパレット、または設定 → ショートカットで割り当てたショートカットから、最近閉じたものから順に再度開けます（近くのキーの組み合わせがすでに使われているため、ショートカットは未割り当てで出荷されます）。再度開いたドキュメントはディスクから読み直されるので、ファイルの現在の状態が表示されます。ファイルが移動または削除されていた場合、タブは復元されず、その理由が通知されます。無題のタブは空の状態で再度開きます。未保存の編集は復元されません——編集中のタブを閉じた時点で、保存するかどうかはすでに確認済みです |
| **ブラウザページ** | **ウィンドウグローバル** — すべてのワークスペースから到達可能 |
| 最近使ったファイル／最近使ったワークスペースのメニュー | グローバル |
| 自動保存、保存の確認、ファイル監視 | 表示・非表示を問わず**すべての**タブが対象 |

切り替えによって何かが閉じることはありません：非表示になったワークスペースのタブはバックグラウンドで開いたままで、自動保存も続き、未保存の変更がある状態でウィンドウを閉じれば保存の確認も表示されます。

## 個別ファイル

どのワークスペースのルートにも属さない場所から開いたファイルは、合成された **個別ファイル** エントリ（ファイルが重なったアイコン）に入ります。そこに切り替えるとそれらのタブが表示されます。このエントリは必要になると自動的に現れます。

## ワークスペース間でのファイルの移動

所属はファイルのパスに従います：

- 別のワークスペースのフォルダーに **名前を付けて保存** すると、タブはそちらに移動します — それが表示中のタブであれば、表示されるワークスペースも一緒に切り替わります。
- ディスク上でのリネームや移動（Finder から行ったものも含む）も、同じようにタブの所属先を移します。
- *非表示の*ワークスペースに属するファイルを（クイックオープン、最近使った項目、ファイルダイアログから）開くと、先にそのワークスペースへ切り替わるので、求めたタブがそのまま目の前に表示されます。

## セッションと再起動

各ワークスペースの設定は、**自分自身のタブ**と分割レイアウト**だけ**を記憶します。人が開いたブラウザページはウィンドウごとに保持されます。Hot Exit はウィンドウのすべてのワークスペースを復元し — ワークスペースごとのサイドバーの状態と、記録された閉じたタブの履歴も含めて — 作業していたワークスペースを再びアクティブにします。

## AI（MCP）の動作

MCP 経由でドキュメントを開く AI クライアントが、表示中のワークスペースを勝手に切り替えることはありません：`workspace.open` は**バックグラウンドタブ**を作成し、後続のドキュメント呼び出しに使う `tabId` を返します。表示内容を変えるのは明示的な `workspace.switch_tab` アクションだけで、そのレスポンスは `workspaceSwitched: true` を報告するので、AI は切り替えが起きたことをあなたに伝えられます。[MCP ツールリファレンス](/ja/guide/mcp-tools)を参照してください。

## レールの操作

| 操作 | 方法 |
|--------|-----|
| ワークスペースを切り替える | そのグリフをクリック |
| ワークスペースを追加する | **ファイル > ワークスペースを開く**（すでにレールにあるフォルダーの場合は、重複させずにそこへ切り替え） |
| 並べ替える | グリフを別のグリフの上にドラッグ |
| 独自のウィンドウへ移動する | グリフをウィンドウの外へドラッグ |
| 新しいウィンドウに複製する | ホバー時の **⧉** ボタン |
| ワークスペースを閉じる | 右クリック → 閉じる。ピン留めされたタブも含め、そのタブはすべて一緒に閉じます。未保存のタブはそれぞれ先に確認し、キャンセルするとワークスペースは残ります |

## ターミナルセッション

レール上の各ワークスペースは、独自のターミナルセッションを持ちます。レールで切り替えると表示されるターミナルタブが入れ替わり、非表示のワークスペースのシェルは手を付けられずに動き続けます — ビジーでもアイドルでも `cd` が入力されることはありません — 戻ると同じシェルが再び表示され、見ていたセッションはワークスペースごとに記憶されています。新しいセッション（**+** ボタン、「ここでターミナルを開く」、「ターミナルで実行」）はアクティブなワークスペースに作成され、そのルートで起動します。ワークスペースを閉じたり独自のウィンドウへ移動したりすると、そのセッションも一緒に閉じます。詳しくは [ターミナルガイド](/ja/guide/terminal#ターミナルセッションとワークスペースレール) を参照してください。

## 既知の制限

macOS では、大文字と小文字の違いだけがある同じフォルダーの 2 つの表記（大文字と小文字を区別しないボリュームで起こりえます）は、**別々の**ワークスペースとして扱われます。これは意図的なものです：ワークスペースの識別は macOS と Linux ではバイト単位で厳密に、Windows では大文字と小文字を区別せずに行われます。
