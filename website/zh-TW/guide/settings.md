# 設定

VMark 的設定面板讓你可以自訂編輯器的每個面向。使用 `Mod + ,` 或透過選單列中的 **VMark > 設定** 開啟。

設定視窗有一個側邊欄，依字母順序（以英文名稱）列出各章節，「關於」放在最下方，「進階」顯示時則位於其下。變更會立即生效——沒有儲存按鈕。

使用側邊欄頂部的**搜尋框**，可依名稱或說明跨所有面板篩選設定——符合的列會集中顯示，因此你不需要知道某個設定位於哪個分類。若要將所有設定恢復為出廠預設值，請使用「關於」章節中的**重設為預設值**。

## 外觀

控制視覺主題與視窗行為。

### 主題

從六款色彩主題中選擇。當前主題以色塊周圍的環形標示。

| 主題 | 背景 | 風格 |
|------|------|------|
| 白色 | `#FFFFFF` | 純淨白，對比度最高 |
| 紙張 | `#EEEDED` | 暖調新聞紙（預設） |
| 薄荷 | `#CCE6D0` | 柔和綠色，護眼 |
| 棕褐 | `#F9F0DB` | 書頁米色，適合長時間閱讀 |
| 夜間 | `#23262B` | 暗色石板，適合弱光環境 |
| Solarized | `#002B36` | Solarized Dark 經典配色 |

::: info Windows 10 與 Linux 只提供白色與夜間
在 Windows 10 與 Linux 上，標題列由系統繪製，而系統只能呈現淺色或深色。因此這兩個平台只提供 **白色** 與 **夜間**，無法與系統視窗外框相符的主題會以兩者中較接近的一個顯示：紙張、薄荷與棕褐顯示為白色，Solarized 顯示為夜間。你儲存的選擇不會被變更——在 macOS 與 Windows 11 上可使用全部主題。在 Windows 11 上，標題列會採用主題本身的顏色；選單列仍以淺色或深色繪製。
:::

#### 跟隨系統外觀

| 設定 | 說明 | 預設 |
|------|------|------|
| 跟隨系統外觀 | 隨系統自動在淺色與深色佈景主題之間切換 | 關閉 |

啟用後，單一的主題列會被兩列取代——**淺色佈景主題**（系統處於淺色模式時使用，預設為紙張）與**深色佈景主題**（深色模式時使用，預設為夜間）。系統外觀一變更，VMark 就會立即在兩者之間切換；你手動選擇的主題會被保留，並在關閉此選項時恢復。

### 側邊欄

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 側邊欄樣式 | 側邊欄與工作區欄的外框樣式。**全高**如 macOS 內建的側邊欄般貼齊視窗邊緣，並以細分隔線與編輯區分開；**卡片**以圓角和陰影浮動於視窗內。同樣適用於設定視窗 | 全高 | 全高、卡片 |

### 視窗

| 設定 | 說明 | 預設 |
|------|------|------|
| 在標題列顯示檔案名稱 | 在 macOS 視窗標題列顯示當前檔案名稱。**僅限 macOS**——其他平台會隱藏此設定，因為 Windows 與 Linux 一律在系統標題列中顯示檔案名稱 | 關閉 |

在 macOS 上，VMark 會在系統標題列之上繪製自己的標題列，因此檔案名稱是該列中可選擇開啟的元素。在 Windows 與 Linux 上，系統會在視窗上方繪製真正的標題列：檔案名稱（有未儲存的變更時帶有 `•`）一律顯示在那裡，VMark 不會另外加上自己的標題列。

### 專注模式

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 變暗程度 | 在專注模式下，非焦點內容變暗的強度。**標準**維持預設的僅變色方式；**強**與**更強**會在此基礎上逐步降低不透明度 | 標準 | 標準、強、更強 |

字型設定、顯示、編輯行為、空白字元與大型檔案設定。

### 字型設計

| 等寬字型 | 程式碼與等寬文字的字型系列——整合終端機也使用此字型 | 系統預設 | 系統預設、SF Mono、Monaco、Menlo、Consolas、DejaVu Sans Mono、Liberation Mono、Ubuntu Mono、Noto Sans Mono、Noto Sans Mono CJK SC、JetBrains Mono、Fira Code、SauceCodePro NFM、IBM Plex Mono、Hack、Inconsolata——以及任何已安裝的字型 |
| 字型大小 | 編輯器內容的基本字型大小 | 18px | 14px、16px、18px、20px、22px |
| 行距 | 行與行之間的垂直間距 | 1.8（寬鬆） | 1.4（緊湊）、1.6（標準）、1.8（寬鬆）、2.0（寬敞）、2.2（超寬） |
| 區塊間距 | 區塊元素（標題、段落、清單）之間的視覺間距，以行距的倍數計算 | 1x（標準） | 0.5x（緊密）、1x（標準）、1.5x（寬鬆）、2x（寬敞） |
| 中日韓文字元間距 | 中日韓文字元之間的額外間距，以 em 為單位 | 關閉 | 關閉、0.02em（極細）、0.03em（輕）、0.05em（標準）、0.08em（寬）、0.10em（更寬）、0.12em（超寬） |

#### 使用你自己安裝的字型

上面列出的名稱只是精選清單，並非上限。三個字型選擇器各自還有一個**已安裝字型**區段，列出電腦上的每個字型系列，因此你安裝的字型——LXGW WenKai、Iosevka、Source Han Serif——選用方式與內建字型完全相同。

在清單最後選擇**自訂…**，即可改為輸入字型系列名稱。請使用系統所回報的確切名稱（macOS：字體簿；Windows：設定 → 個人化 → 字型）— 以 LXGW WenKai / 霞鹜文楷 為例，名稱是 `LXGW WenKai`。名稱輸入完整後字型就會立即套用；如果沒有任何變化，表示該名稱與已安裝的字型系列不符。包含引號、逗號、分號或括號的名稱會被拒絕，該列也會顯示提示。

::: tip 已安裝字型僅限 macOS
macOS 會為你列出每個已安裝的字型系列。在 Windows 與 Linux 上，該區段是空的，需透過**自訂…**選用——輸入字型系列名稱的方式在三個平台上完全相同。
:::

此選擇也會套用到 PDF 匯出，因為它透過同一個引擎、以相同的字型算繪。HTML 匯出無法將你電腦上的字型打包進去，因此匯出的頁面會退回使用讀者自己的字型，除非對方也安裝了同一個字型系列。

### 顯示

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 編輯器寬度 | 最大內容寬度。較寬的值適合大型螢幕；較窄的值提升可讀性 | 50em（中等） | 36em（緊湊）、42em（窄）、50em（中等）、60em（寬）、80em（超寬）、不限 |

::: tip 同樣的寬度，拉丁文與中日韓文讀起來不同
編輯器寬度以 `em` 計算，因此以*字元*計的行長取決於文字系統：在 50em 下，一行拉丁文約可容納 90–100 個字元（約為排版上 45–75 字元行長的 2 倍，適合雙窗格編輯器），而一行中日韓文約可容納 50 個全形字元——正好落在中文傳統的 40–60 字範圍內。如果你主要撰寫拉丁文散文並想要書籍般的行長，請選擇 36–42em；以中日韓文為主的文件，預設值就已經是經典行長。
:::

::: tip
50em 在 18px 字型大小下約為 900px——對大多數顯示器而言是舒適的閱讀寬度。
:::

### 貼上與輸入

| 圖片與圖表邊框 | 是否在圖片、Mermaid 圖表與數學區塊周圍顯示邊框。僅作用於編輯器——不套用於匯出或列印 | 無 | 無、始終、懸停時 |

### HTML 渲染

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 所見即所得中的原始 HTML | 控制原始 HTML 區塊在所見即所得模式中的渲染方式 | 淨化 | 隱藏、淨化、淨化 + 樣式 |
| 允許的 HTML 標籤 | 算繪的標籤集合範圍有多廣 | 嚴格 | 嚴格、擴充 |
| 額外允許這些標籤 | 額外允許的標籤名稱，以逗號分隔 | _（空白）_ | 例如 `kbd, samp, var` |

::: tip
**隱藏** 會收合原始 HTML，不算繪任何內容。**淨化** 在去除危險標籤後渲染 HTML。**淨化 + 樣式** 則額外保留行內 `style` 屬性中安全的子集。

**嚴格** 只允許一小組保守的標籤。**擴充** 另外會算繪 `<svg>`（及其安全的子元素）、`<figure>`/`<figcaption>`、`<details>`/`<summary>` 以及其他語意/結構標籤——全都仍經過淨化。使用 **額外允許這些標籤** 可在此之上加入特定的額外標籤（例如 `kbd, samp, var`）。
:::

::: warning
無論這些設定為何，危險標籤（`<script>`、`<style>`、`<iframe>`、`<form>`、事件處理器……）**一律**會被移除——自訂標籤欄位無法重新啟用它們。允許清單的範圍只影響所見即所得預覽；檔案中的原始 HTML 永遠不會被修改。
:::

### 結束行為

| 設定 | 說明 | 預設 |
|------|------|------|
| 確認結束 | 結束時需要按兩次 `Cmd+Q`（或 `Ctrl+Q`），防止意外退出 | 開啟 |
| 關閉時最小化至系統匣 | **僅限 Windows。** 關閉最後一個視窗時，VMark 會繼續在系統匣中執行，而不是結束 | 關閉 |

**關閉時最小化至系統匣** 只會改變*最後一個*視窗的行為。開啟多個視窗時，關閉其中一個仍會將它關閉；只有最後一次關閉——也就是原本會結束 VMark 的那一次——會改為把它停放到系統匣中。不會關閉任何內容，因此未儲存的工作會完全保留在原處。

- **左鍵點擊**系統匣圖示即可叫回 VMark。
- **右鍵點擊**可選擇 **顯示 VMark** 與 **結束 VMark**。從系統匣結束時會先把視窗叫回來，讓任何未儲存變更的提示出現在你能回應的地方。
- `Ctrl+Q` 仍照常結束。
- 在 VMark 位於系統匣時關閉此設定，會在圖示消失前先把視窗叫回來，因此絕不會讓 VMark 在沒有視窗也沒有圖示的狀態下執行。

## 整合

MCP 伺服器與 AI 供應商設定。

### MCP 伺服器

MCP（模型情境協定）伺服器允許 Claude Code 和 Cursor 等外部 AI 助理以程式方式控制 VMark。

| 設定 | 說明 | 預設 |
|------|------|------|
| 啟用 MCP 伺服器 | 啟動或停止 MCP 伺服器。執行中時，狀態徽章會顯示連接埠和已連線的用戶端 | 開啟（切換） |
| 啟動時自動開始 | VMark 開啟時自動啟動 MCP 伺服器 | 開啟 |
| 自動核准儲存至新位置與精靈結果 | 讓 MCP 用戶端不經詢問即可將文件儲存到新位置，並讓精靈直接套用其結果而不顯示預覽。關閉時，MCP 儲存到新路徑的請求會被拒絕，並以提示訊息通知你。MCP 的文件寫入永遠不受此設定限制——每次寫入都會記入代理程式編輯歷史，並可從狀態列的 MCP 寫入歷史還原 | 關閉 |

伺服器執行中時，面板還會顯示：
- **連接埠**——自動分配；AI 用戶端透過設定檔發現
- **版本**——MCP 伺服器附屬元件版本
- **工具 / 資源**——可用 MCP 工具與資源的數量
- **已連線用戶端**——目前已連線的 AI 用戶端數量

在 MCP 伺服器部分下方，你可以一鍵將 VMark 的 MCP 設定安裝至受支援的 AI 用戶端（Claude Desktop、Claude Code、Codex CLI、Gemini CLI）。

完整詳細資訊請參閱 [MCP 設定](/zh-TW/guide/mcp-setup)與 [MCP 工具參考](/zh-TW/guide/mcp-tools)。

### AI 供應商

設定驅動 [AI 精靈](/zh-TW/guide/ai-genies)的 AI 供應商。每次只能啟用一個供應商。

**CLI 供應商**——使用本機安裝的 AI CLI 工具（Claude、Codex、Gemini）。點選 **偵測** 以掃描你的 `$PATH` 中可用的 CLI。CLI 供應商使用你的訂閱方案，不需要 API 金鑰。

**REST API 供應商**——直接連接至 API：Anthropic、OpenAI、**OpenAI 相容**服務（DeepSeek、Groq、OpenRouter……）、Google AI，或本機的 Ollama 伺服器（Ollama API）。每個都需要模型名稱與 API 金鑰——但 Ollama 的金鑰為選填。除 Google AI 外都還需要端點，有標準端點的供應商已預先填好（OpenAI 相容欄位沒有標準端點，需自行輸入）。

每個供應商的詳細設定說明，請參閱 [AI 供應商](/zh-TW/guide/ai-providers)。

## 格式

非預設格式轉接器的選擇性啟用切換，以及唯讀程式碼分頁外部編輯器指令的顯式設定。

Markdown、純文字和 YAML/YML **一律**已登錄——這是沉穩的預設值。所有其他轉接器**預設為關閉**，避免升級時讓現有使用者感到意外。切換後，格式登錄檔會即時重建；已開啟的分頁會以正確的轉接器重新掛載，無需重新啟動。

完整格式清單與預覽說明，請參閱[支援的格式](/zh-TW/guide/formats)。

### 格式支援

| 切換項目 | 預設 | 啟用 |
|---|---|---|
| **資料格式** | 關閉 | `.json`、`.jsonl`、`.toml`——分割面板：原始碼 + 可導覽樹狀結構。支援 `Cargo.toml`、`package.json`、`pyproject.toml` 的結構感知預覽。 |
| **圖表與 SVG** | 關閉 | `.mmd`（Mermaid）和 `.svg`——分割面板：原始碼 + 淨化後的即時渲染。 |
| **HTML 預覽** | 關閉 | `.html` 和 `.htm`——沙盒 iframe 預覽（空的 `sandbox=""` 允許清單、DOMPurify、CSP `<meta>`）。其安全審核簽署仍在進行中，預覽中也會如此提示——請見[HTML 安全模型](/zh-TW/guide/formats#html-安全模型)。 |
| **程式碼檢視器** | 關閉 | 12 個唯讀檢視器（`.ts`、`.tsx`、`.js`、`.jsx`、`.py`、`.rs`、`.go`、`.css`、`.sh`、`.bash`、`.rb`、`.lua`）。以語法高亮的檢視器開啟，提供**啟用編輯**和**在外部編輯器中開啟**按鈕。 |

當某個分類關閉時，對應的副檔名會退回至純文字模式，檔案仍可開啟，只是不會顯示結構視圖。

### 預設檢視模式

支援預覽的檔案（HTML、SVG、Mermaid、JSON、YAML、TOML）會以三種[檢視模式](/zh-TW/guide/formats#檢視模式-原始碼-分割-預覽)之一開啟：

| 選項 | 結果 |
|---|---|
| **原始碼** | 可編輯的原始碼窗格，佔滿全寬。 |
| **分割**（預設） | 原始碼與預覽並排。 |
| **預覽** | 唯讀算繪，佔滿全寬。 |

這是新開啟分頁的預設值；每個分頁會記住自己的選擇，你也可以用畫面上的切換按鈕或 `F6` / `Shift + F6` 切換任何分頁。

### 外部編輯器

針對唯讀程式碼分頁上的**在外部編輯器中開啟**按鈕，選取應啟動的編輯器：已知編輯器的名稱（`code`、`zed`、`subl`、`vim`…），或應用程式套件（例如 `/Applications/Visual Studio Code.app`）或可執行檔的完整路徑。shell、直譯器與終端機模擬器會被拒絕，不存在的路徑也是。

圖形介面設定會覆蓋所有環境變數——明確勝於隱含。留空可使用環境變數備用鏈 `$VMARK_EXTERNAL_EDITOR → $VISUAL → $EDITOR → 平台預設`。完整解析順序與安全閘道請見[在外部編輯器中開啟](/zh-TW/guide/formats#在外部編輯器中開啟)。

### 一次性升級提示

升級至多格式支援後首次啟動時，VMark 會顯示非阻斷性的提示通知，引導你前往**設定 → 格式**。此提示每次安裝只出現一次——顯示或關閉後不再重複出現。

### 檔案類型覆寫

除了分類切換之外，你還可以透過命令面板覆寫個別檔案系列的開啟方式——**設定檔案類型：純文字 / Markdown / 恢復預設**。覆寫依檔案系列儲存（依副檔名，或對 `.env` 這類檔案依點檔案主檔名），並會跨工作階段保留。請見[VMark 如何決定檔案類型](/zh-TW/guide/formats#vmark-如何決定檔案類型)。

**格式** 面板會列出你設定的每一項覆寫，每項以 `key → format` 呈現。使用各項的 `×` 按鈕移除單一項目，或使用 **全部清除** 一次移除全部——移除的項目會回復為內建規則。

## 快捷鍵

檢視並自訂所有鍵盤快捷鍵。快捷鍵按類別分組（檔案、編輯、檢視、格式等）。

- **搜尋**——依名稱、類別或按鍵組合過濾快捷鍵

- **重設**——將個別快捷鍵還原為預設，或一次全部重設
- **匯出 / 匯入**——將自訂綁定儲存為 JSON 檔案，並在另一台機器上匯入

完整的預設快捷鍵參考請參閱[鍵盤快捷鍵](/zh-TW/guide/shortcuts)。

| 螢幕閱讀器模式 | 將終端機輸出提供給輔助技術（VoiceOver）。基於效能考量預設關閉 | 關閉 | 開啟 / 關閉 |

這裡還有兩個平台專用的開關，預設皆為開啟：**將 Option 作為 Meta 鍵**（僅 macOS——將 Option 鍵視為 Meta，emacs、tmux 等工具在 `Alt` 前綴快捷鍵與逐詞移動時需要它；如果你需要用 Option 死鍵輸入重音字母，例如 `Option + E`，請關閉它）與 **Shell 整合**（在 Windows 上隱藏——向 zsh 與 bash 注入命令標記，以支援提示字元導覽、結束狀態標示與目前目錄追蹤；從新的終端機工作階段開始生效）。

## 關於

顯示應用程式版本、網站與 GitHub 儲存庫連結，以及更新管理。**第三方聲明**連結會以系統預設的文字檔應用程式開啟 VMark 所附帶之開源軟體的授權條款全文。

### 更新

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 自動更新 | 定期檢查是否有新版本 | 開啟 | 開啟 / 關閉 |
| 檢查頻率 | 檢查更新的頻率。僅在開啟自動更新時可用 | 啟動時 | 啟動時、每天、每週、僅手動 |
| 自動下載更新 | 有新版本時在背景下載 | 關閉 | 開啟 / 關閉 |
| 立即檢查 | 手動觸發更新檢查 | — | — |

有更新可用時，會出現一個顯示新版本號、發布日期和版本說明的卡片。你可以 **下載** 更新、**跳過** 此版本，或——下載後——**重新啟動以更新**。

#### 更新會符合你安裝 VMark 的方式

更新程式下載的是與你安裝時相同的套件格式，而不是每個平台固定一種：

| 你安裝的是 | 更新程式取得的是 |
|---|---|
| macOS `.dmg` | 已簽署的應用程式套件 |
| Windows `.exe`（NSIS） | `.exe` 安裝程式 |
| Windows `.msi` | `.msi` 套件 |
| Linux `.deb` | `.deb` 套件 |
| Linux `.rpm` | `.rpm` 套件 |
| Linux AppImage | AppImage |

在 Linux 上，更新 `.deb` 或 `.rpm` 安裝會執行系統套件管理員，因此會要求你進行驗證——安裝系統套件需要 root 權限。AppImage 更新則會直接就地取代檔案，不需要任何提示。

#### 如果更新卡住

檢查與下載都需要透過網路，而一個卡住而非直接失敗的連線，原本可能讓更新永遠停留在進行中。如果檢查一分鐘內沒有進展，或下載、安裝三分鐘內沒有進展，VMark 會在文件視窗中顯示一則常駐的 **更新已停滯** 通知。其 **重試** 按鈕會讓更新程式回到閒置狀態，讓你可以再試一次——本章節中的 **立即檢查**，或下一次自動檢查，都會從全新的檢查重新開始。

更新活動會寫入日誌檔案，因此如果問題反覆發生，值得將日誌附在錯誤回報中：

| 平台 | 日誌位置 |
|---|---|
| macOS | `~/Library/Logs/app.vmark/` |
| Windows | `%LOCALAPPDATA%\app.vmark\logs\` |
| Linux | `~/.local/share/app.vmark/logs/` |

### 重設

| 設定 | 說明 |
|------|------|
| 重設為預設值 | 將這些面板中的設定還原為預設值。會先出現確認提示——此操作無法復原 |

## 進階

::: tip
「進階」部分預設為顯示——它提供預設開啟的內嵌瀏覽器的關閉開關。在設定視窗中按 `Ctrl + Option + Cmd + D` 可將其隱藏，再按一次即可恢復顯示。
:::

開發者與系統層級設定。

### 連結協定

| 設定 | 說明 | 預設 |
|------|------|------|
| 自訂連結協定 | VMark 視為連結的額外 URL 協定。以標籤形式輸入每個協定 | `obsidian`、`vscode`、`dict`、`x-dictionary` |

這份清單有兩個作用。插入連結時，剪貼簿中使用這些協定的 URL 會像 `https://` 一樣被辨識為連結。開啟連結時，只有協定為 `http`、`https`、`mailto` 或在此清單中的連結，VMark 才會交給系統開啟——因此 `obsidian://open?vault=...` 與 `vscode://file/...` 連結會在對應的應用程式中開啟，其他協定則會被拒絕。少數協定無論清單內容為何都無法啟用：`javascript:`、`data:`、`file:` 等。

你移除的預設協定會維持移除狀態。之後的 VMark 版本新增的預設協定，會在該版本首次啟動時加入你的清單，且只加入一次。

### 效能

| 設定 | 說明 | 預設 |
|------|------|------|
| 保持兩種編輯器啟用 | 同時掛載所見即所得與原始碼模式編輯器，以加快模式切換速度。會增加記憶體使用量 | 關閉 |

### 一致性

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 語意檢查信心度 | 檢查的答案必須有多確定，才會被記錄為判定結果。低於此值時，答案仍會保留，但標示為未知 | 0.9 | 0.7、0.8、0.9、0.95 |

什麼是檢查、判定結果如何記錄，請參閱[一致性](/zh-TW/guide/coherence)。

### 工作流程檔案

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 取得 Action 中繼資料 | 允許 VMark 從所參照的 GitHub Actions 取得 `action.yml`，以填入結構化編輯器的 `with:` 表單。關閉後可讓工作流程編輯器完全離線 | 開啟 | 開啟 / 關閉 |
| 可用時使用 actionlint | 如果 `actionlint` 可執行檔在你的 PATH 中，會對工作流程檔案執行它以取得更豐富的診斷。若未安裝該可執行檔則沒有作用 | 開啟 | 開啟 / 關閉 |

### 工作流程

GitHub Actions 檢視器沒有開關：開啟 `.github/workflows/` 下的檔案就會顯示圖與表單編輯器，原始碼窗格的輔助功能（運算式補全、游標與畫布同步、`uses:` 跳至定義）也會一併載入。這裡剩下的是檢視器唯一的偏好設定，以及獨立的執行引擎。

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 保留 YAML 格式 | 透過表單面板儲存工作流程編輯時，使用 CST 來回流程保留原始 YAML 的註解、錨點、鍵順序與空行。關閉時，儲存使用較精簡的序列化器（較快但會失真） | 開啟 | 開啟 / 關閉 |
| 工作流程引擎 | 執行 VMark 自己的 YAML 工作流程檔案：工作流程檔案開啟時，原始碼旁會顯示它的步驟圖與執行 / 取消工具列，工作流程精靈也能執行。步驟可能呼叫 AI 供應商並寫入檔案，因此在你主動要求之前會保持關閉 | 關閉 | 開啟 / 關閉 |

引擎不會改變檢視器顯示的內容：無論引擎是否開啟，GitHub Actions 檔案都會在檢視器中開啟；引擎關閉時，VMark 工作流程檔案會顯示為一般的 YAML 樹狀結構。引擎關閉時，VMark 也會直接拒絕工作流程執行請求，而不只是隱藏按鈕——包括透過 MCP 送達的請求——並回報「工作流程引擎已在設定中關閉」。

這兩列都位於 **開發者工具**（見下文）之下——開啟開發者工具即可顯示它們。檢視器請參閱[工作流程檢視器](/zh-TW/guide/workflow-viewer)，引擎請參閱 [精靈工作流程](/zh-TW/guide/workflows)。

### 內嵌瀏覽器

| 設定 | 說明 | 預設 | 選項 |
|------|------|------|------|
| 內嵌瀏覽器 | 應用程式內的網頁瀏覽器（僅限 macOS）。開啟時，**新增瀏覽器分頁** 會出現在「檔案」選單與命令面板中，且可使用 MCP 的 `browser` 工具。關閉時會關閉已開啟的瀏覽器分頁，並撤除 AI 自動化介面 | 開啟 | 開啟 / 關閉 |
| AI 瀏覽器工作階段 | 選擇 `Sandbox`（建議，隔離且不持久保存的 AI Cookie）或 `Shared profile`（使用者的設定檔，前往目標網站前需經核准） | 沙箱 | 沙箱 / 共享 |
| 允許 AI 回送存取 | 允許 AI 導覽至 localhost 和回送位址。私有區域網路、中繼資料和連結本機位址範圍仍被封鎖 | 關閉 | 開啟 / 關閉 |

這些設定位於 **進階 → macOS** 下，且只在 macOS 上顯示。兩列 AI 相關設定只有在瀏覽器開關開啟時才會出現，而且不受開關開啟與否的影響——在你變更之前，它們會一直維持沙箱 / 封鎖回送存取。完整功能介紹請參閱[內嵌瀏覽器](/zh-TW/guide/browser)。

### 平台專用

| 設定 | 說明 | 預設 | 平台 |
|------|------|------|------|
| 開啟時清除 macOS 隔離標記 | 開啟工作區時，從工作區資料夾及其中直接包含、VMark 能開啟的檔案上移除 macOS 下載隔離屬性（`com.apple.quarantine`）（不處理子資料夾）。否則在 VMark 執行時，macOS 可能會默默忽略你在 Finder 中雙擊已下載檔案的動作。介面中顯示為 **進階 → macOS** 下的 **開啟工作區時清除下載隔離標記** | 開啟 | macOS |

### 開發者工具

**開發者工具** 是實驗性與僅供開發使用之設定的持久主開關。開啟後會顯示 **保留 YAML 格式** 列、**工作流程引擎** 開關，以及 **熱退出開發工具** 面板（內含測試工作階段擷取、檢查、還原、清除和重新啟動的按鈕）。由於此開關會持久保存，你啟用的開發中功能在不同工作階段以及發行版中都能持續使用——不必每次開啟設定時都重新啟用開發者工具。

它也會在設定之外顯示[知識庫](/zh-TW/guide/knowledge-base)：**檢視 → 知識庫** 選單項目、命令面板指令與 `Ctrl + Shift + 4` 快捷鍵在開啟開發者工具之前都會隱藏，因為目前任何平台的發行版都不附帶此功能所需的內容伺服器執行環境。

| 設定 | 說明 | 預設 |
|------|------|------|
| 開發者工具 | 啟用開發者模式，並顯示下方實驗性與僅供開發使用的設定 | 關閉 |
