# 工作流程精靈

**工作流程精靈**是一個[精靈工作流程](/zh-TW/guide/workflows)——一條多步驟的 YAML 流程——以 `.yml` 或 `.yaml` 檔案的形式存放在精靈資料夾中。它會出現在精靈挑選器（`Mod + Y`）與**編輯 → 精靈**中，與 Markdown 精靈完全相同；選取後，會透過工作流程引擎執行整條流程，而不是送出單一提示詞。

## 需求

| 需求 | 原因 |
|------|------|
| 開啟**設定 → 進階 → 開發者工具**，再開啟**工作流程引擎** | 引擎預設為關閉。引擎關閉時，挑選器仍會列出工作流程精靈，但執行時會失敗並顯示「工作流程引擎已在設定中關閉」 |
| 已開啟的工作區 | `action/save-file` 等動作步驟會以工作區根目錄解析路徑；若沒有工作區，VMark 會顯示提示訊息，且不會開始執行 |
| 已設定的 [AI 供應商](/zh-TW/guide/ai-providers) | 精靈步驟會呼叫目前使用中的供應商，與 Markdown 精靈使用的相同 |

## 撰寫工作流程精靈

將 YAML 檔案放在精靈資料夾（**編輯 → 精靈 → 開啟精靈資料夾**）下的任何位置；與 Markdown 精靈一樣，子資料夾會成為分類。挑選器以檔案名稱作為精靈名稱，並以 YAML 的 `description`（若無則用其 `name`）作為第二行說明。工作流程精靈的範圍是整份文件——執行時沒有可處理的選取內容——因此每個步驟都要自行提供 `with: { input: … }`，而它呼叫的 Markdown 精靈會原封不動地將其綁定到 `{{content}}` 佔位符。

內建的 `triage-and-translate.yml` 範例是現成的起點：將它複製到資料夾中，並替換種子文字。它的存放位置、完整的 YAML 結構描述、運算式、核准、各步驟的模型與逾時設定，都記載於[精靈工作流程](/zh-TW/guide/workflows)；工作流程精靈的執行會照常進行，核准對話框也會照常出現，但它不會顯示即時步驟圖，也無法從工作流程面板取消（執行期間，面板上的「執行」會回報引擎忙碌中），面板也不會為它提供「還原檔案」。

另請參閱 [AI 精靈](/zh-TW/guide/ai-genies)，了解單一提示詞的 Markdown 精靈格式。
