# 工作區導軌

::: warning 實驗性
工作區導軌是實驗性功能，**預設為關閉**。請在 **設定 → 檔案與圖片 → 工作區 → 工作區側欄** 中啟用。導軌關閉時，VMark 的行為與過去完全相同 — 每個視窗一個工作區。
:::

工作區導軌讓一個視窗**同時容納多個工作區**，並以一條由彩色圖示組成的垂直長條顯示在左側邊緣。點按某個工作區會進行**完整的情境切換**：編輯器分頁、側邊欄檔案樹、分割窗格版面，以及側邊欄／大綱狀態，全都會換成該工作區自己的一組 — 就像在瀏覽器中切換空間，而不只是變更篩選條件。

## 哪些會切換，哪些保持不變

| 介面 | 導軌切換時 |
|---------|------------------|
| 編輯器分頁列 | 只顯示作用中工作區的分頁（以及瀏覽器網頁） |
| 側邊欄檔案樹 | 以作用中工作區為根目錄重新呈現，並保有它自己的資料夾展開與捲動狀態 |
| 分割窗格 | 每個工作區記住自己的分割版面 |
| 大綱 | 每個分頁的收合／篩選／捲動狀態跟隨工作區 |
| 下一個／上一個分頁、分頁右鍵選單、快速開啟的「已開啟分頁」 | 限定於作用中工作區 |
| 重新開啟已關閉的分頁 | 已關閉的分頁按工作區分別記錄（另有一個共用的瀏覽器範圍），並可從 **檔案 → 重新開啟已關閉的分頁**、指令面板，或你在 設定 → 快捷鍵 中指定的快捷鍵，依由新到舊的順序重新開啟（它出廠時未指定快捷鍵：附近的組合鍵都已被占用）。重新開啟的文件會從磁碟重新讀取，因此顯示的是檔案目前的內容；若檔案已被移動或刪除，該分頁不會還原，並會有提示說明原因。未命名的分頁重新開啟時為空白。未儲存的編輯不會被找回——關閉有未儲存變更的分頁時，早已詢問過是否儲存 |
| **瀏覽器網頁** | **視窗全域** — 在每個工作區都能存取 |
| 最近使用的檔案／最近使用的工作區選單 | 全域 |
| 自動儲存、儲存提示、檔案監看 | 涵蓋**每一個**分頁，無論是否隱藏 |

切換絕不會關閉任何東西：隱藏工作區的分頁會在背景中保持開啟、持續自動儲存，而且當你關閉含有未儲存變更的視窗時，仍會收到儲存提示。

## 獨立檔案

從所有工作區根目錄之外開啟的檔案，會放在一個合成的 **獨立檔案** 項目中（堆疊檔案圖示）。切換到它就會顯示這些分頁；需要時它會自動出現。

## 在工作區之間移動檔案

歸屬跟隨檔案的路徑：

- 以 **另存新檔** 存到另一個工作區的資料夾，會把該分頁移過去 — 而且如果那正是你正在看的分頁，可見的工作區也會跟著它過去。
- 在磁碟上重新命名或移動（包括從 Finder 操作）也會以同樣方式為分頁重新找到歸屬。
- 開啟屬於*隱藏*工作區的檔案（透過快速開啟、最近使用的項目或檔案對話框）時，會先切換到該工作區，讓你要求的分頁就是你看到的分頁。

## 工作階段與重新啟動

每個工作區的設定**只記住它自己的分頁**與分割版面。由使用者開啟的瀏覽器網頁按視窗保存。熱退出會還原視窗中的每一個工作區 — 包括每個工作區的側邊欄狀態與已記錄的已關閉分頁歷史 — 並重新啟用你原本所在的工作區。

## AI（MCP）行為

透過 MCP 開啟文件的 AI 用戶端絕不會強行切換你可見的工作區：`workspace.open` 會建立一個**背景分頁**，並回傳其 `tabId` 供後續的文件呼叫使用。只有明確的 `workspace.switch_tab` 動作會改變你看到的內容，而它的回應會回報 `workspaceSwitched: true`，讓 AI 可以告訴你發生了切換。請參見 [MCP 工具參考](/zh-TW/guide/mcp-tools)。

## 導軌操作

| 操作 | 方式 |
|--------|-----|
| 切換工作區 | 點按其圖示 |
| 新增工作區 | **檔案 > 開啟工作區**（已在導軌上的資料夾會直接切換過去，而不會重複加入） |
| 重新排序 | 將圖示拖曳到另一個圖示上 |
| 移到獨立視窗 | 將圖示拖出視窗 |
| 複製到新視窗 | 游標停留時出現的 **⧉** 按鈕 |
| 關閉工作區 | 按右鍵 → 關閉。它的所有分頁都會一併關閉，釘選的分頁也包括在內；每個有未儲存變更的分頁都會先提示，取消則保留該工作區 |

## 終端機工作階段

導軌上的每個工作區都擁有自己的終端機工作階段。導軌切換會替換可見的終端機標籤；隱藏工作區的 shell 會原封不動地繼續執行 — 無論忙碌或閒置，都不會有 `cd` 被輸入 — 切換回來時會再次顯示同樣的 shell，而且每個工作區都會記住你原本正在看的工作階段。新的工作階段（**+** 按鈕、「在此開啟終端機」、「在終端機中執行」）會建立在作用中的工作區，並從它的根目錄啟動；關閉工作區或將它移到獨立視窗時，會一併關閉其工作階段。詳情請見[終端機指南](/zh-TW/guide/terminal#終端機工作階段與工作區導軌)。

## 已知限制

在 macOS 上，同一個資料夾的兩種寫法若只有大小寫不同（在不區分大小寫的磁碟區上可能發生），會被視為**不同的**工作區。這是刻意的設計：在 macOS 與 Linux 上，工作區身分以位元組完全比對；在 Windows 上則不區分大小寫。
