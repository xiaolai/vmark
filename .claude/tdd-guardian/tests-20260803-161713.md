## Cross-cutting notes (amended 2026-08-03 after Codex cross-review — see `dev-docs/audit/20260803-crosscutting-notes-codex-review.md`)

1. **Mock-boundary policy is enforced FIRST, not retroactively**: WI-18's gate lands before WI-1, so every matrix above is written under enforcement, not discipline. The gate freezes an identity baseline — (file, mocking API, resolved target) triples across ALL Vitest mocking variants (`vi.mock`, `vi.doMock`, dynamic forms, relative paths, `__mocks__/`) and all test-adjacent files including `src/test/` helpers. Counts are banned (like-for-like swaps pass counts). "Real store object" is not "real composed behavior": the global setup.ts `invoke` fake still resolves-by-default, so composition claims belong to WI-17's loud-fail fake, not to using real Zustand alone.
2. **Pin invariants at RED; pin mechanisms only when user-visible; consequential decisions go to the ledger** (`.claude/tdd-guardian/decisions-20260803.md`), not one-line test headers. WI-1: the invariant is "a stale write can never happen" — remap-vs-close is mechanism, decidable after RED. WI-15: strip-vs-reject is NOT one decision — persistence boundaries need passthrough (forward compat) while untrusted MCP input needs explicit posture per operation class; strip is what buried `windowId`. WI-17: the save-vs-external-change winner is a data-integrity protocol (disk bytes, dirty state, mtime, notification) recorded as ledger entry D6. Checker-correctness questions (comment counting, `doMock` coverage) are NOT decisions — they derive from the gate's threat model: parse imports, count every variant, no channel keeps the documented comment-counting landmine.
3. **Durable meta-tests replace recorded-not-committed RED proofs**: a PR record proves one version of one gate failed once; a committed, passing meta-test that injects the violation at runtime into an ISOLATED fixture tree / scratch git repo (never the shared checkout — the repo's own selftest-interruption incident is the reason) proves the gate keeps biting. Applied: WI-8/WI-10 dep-cruiser fixture trees, WI-16 scratch-git base/head pairs (making its test-PR demo redundant), WI-5's Stryker canary project with a known surviving mutant. One-time live demos survive only as supplementary acceptance for expensive live paths (WI-17's gutted-save demo, WI-4's deliberately-failing dispatch).
4. **Config gates are layered, not single-shot**: (a) structural wiring check (workflow parses, step exists with correct `if:`, package.json actually invokes the script); (b) durable negative canary (note 3); (c) exact-SHA positive acceptance — `gh workflow run --ref` + `gh run view --json headSha,conclusion,jobs`, never a bare `gh run watch`; (d) recurring liveness (on-failure issue steps now; periodic gate-health audit deferred). Special case: `lint:eager` must be EXTENDED before WI-12/13 may cite it — today it checks 4 chunk families in `dist/index.html` and cannot see xyflow/codemirror/tiptap/GHA-workbench; the extended denylist is RED against today's build, which is the true RED these WIs need.
5. **Subprocess tests are the mandatory minimum layer, not the only shape**: every gate script gets real-CLI execution over tmpdir fixtures (exit code + stderr content), PLUS focused pure/property tests for parsing logic where it exists, PLUS a wiring check that `check:all`/CI invokes the script (a perfectly tested unwired checker is dead — the mutation-workflow lesson), PLUS a current-tree applicability run where meaningful. Fixture roots use sentinel names so a passing test proves the script read the fixture, not the real repo; scripts anchored to `import.meta.url` gain an explicit `--root` parameter. The `gh` stub validates argv and fails on unexpected calls (a stub answering anything lets the script query the wrong repo/SHA and pass); subprocess calls carry timeouts.
