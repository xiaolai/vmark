## Decisions made in this revision

Revision 1 left these open. Open questions are not executable, so each is now
decided. Reversing one is a plan change, not an implementation choice.

| # | Question | Decision | Why |
|---|---|---|---|
| D1 | BOM in canonical editor text | **Stripped.** Add `hasBom: boolean` to document metadata; `saveToPath` re-emits it. | A U+FEFF living at offset 0 of the editor buffer breaks offset-0 block detection and shows as an invisible character. Round-trip fidelity is preserved by metadata, not by carrying the character. |
| D2 | Mixed line endings | **Pin CURRENT behaviour** (`detectLineEnding` returns `crlf` if any CRLF occurs) with a characterisation test. Majority-rule is a **deferred product decision**, not part of this work. | Rev 1 said "dominant convention", which the current code does not implement. Changing EOL detection policy is scope creep on a plan whose goal is the LF invariant. |
| D3 | Text domains | Three names, used in code and tests: **`rawDiskText`** (bytes as decoded, CRLF + BOM), **`canonicalEditorText`** (LF, no BOM — what `content` holds), **`preprocessedParserText`** (canonical text after `normalizeBareListMarkers` / `preprocessEscapedMarkers`). **All production structure offsets target `canonicalEditorText`.** | Rev 1's `raw.slice(start, end)` check silently assumed one domain. Offsets diverge after the first CRLF, which is a wrong-range bug in exactly the destructive actions this work protects. |
| D4 | `document` vs `source-position` equality | **Not equality.** A **normalised semantic projection** with an explicit, enumerated delta list for repaired inputs. | `normalizeBareListMarkers` deliberately appends a space so `  -` becomes a list item. The two trees differ **by design**; rev 1's zero-divergence criterion was impossible. |
| D5 | Structure-service scope | **Source mode only.** WYSIWYG already holds a parsed document (the PM tree). No Markdown↔ProseMirror position map is built. | Rev 1 implied one resolver served both surfaces. Markdown offsets cannot be applied to PM selections. |
| D6 | Coverage authority | `vitest.config.ts` ratchet floors govern. **WI-0.2 aligns the tdd-guardian config to match** rather than leaving two live sources. | The reviewer agreed vitest governs project gates but correctly refused "assume" while the plugin carries its own 100/100/100/100. |

### WI-0.1: Web Worker feasibility spike
**Status:** DONE — 2026-07-31 (viable; one criterion answered by build inspection, not runtime)
**Changed:** none (spike — probe wired in, built, inspected, reverted; `main.tsx` clean, typecheck clean)
**Verified:** `pnpm build` exit 0 with a probe worker in the module graph; emitted
`dist/assets/probe.worker-*.js` referenced as `new Worker(new URL("/assets/probe.worker-*.js", import.meta.url))`

**VERDICT: the worker path is VIABLE. Phases 4–9 are unblocked.**

**Findings (measured):**

1. **Vite emits a same-origin FILE worker, never a blob.** The built output
   constructs `new Worker(new URL("/assets/probe.worker-<hash>.js", import.meta.url))`,
   and no blob-constructed worker appears anywhere in `dist/`. CSP declares
   `script-src 'self'` with **no `worker-src`**, so the chain
   `worker-src → child-src → script-src` applies `'self'` — which permits a
   same-origin asset. A `blob:` worker would have been blocked; Vite does not
   produce one.
2. **The dev runtime CANNOT answer the CSP question, and nearly gave a false
   pass.** `pnpm tauri:dev` serves from the Vite dev server over
   `http://localhost:1420` with `cspMetaTag: null` and `cspHeader: null` — the
   production CSP is not enforced at all. A blob worker was observed ALLOWED
   there, which is meaningless for the shipped app. The Tauri MCP harness is
   debug-only (absent in release builds), so runtime CSP verification is not
   available by that route either. **Build-output inspection is the correct
   oracle here, not runtime.**
3. **Main-thread parse of 1.26 MiB takes 720 ms** (19,419 top-level blocks) —
   worse than the ~400 ms/10K-lines figure in the architecture doc. The UI stall
   is real.
4. **`structuredClone` of a 19,419-entry index takes 5.2 ms.** Transfer is not
   the bottleneck; the parse is.
5. **A naive index is 86.6% of document size** — 1117 KiB for 1.26 MiB. A
   **design constraint on WI-4.1**: "compact" is not achieved by one object per
   block. The byte budget must be met by a real encoding (parallel typed arrays,
   or a flat offset buffer with a separate type table).

**CI coverage gap (feeds WI-9.2):** `check:all` runs jsdom only. The evidence
above comes from build-output inspection, which IS automatable — a gate
asserting no `blob:`-constructed worker in `dist/` would catch a regression
without needing a browser tier. Runtime worker behaviour (termination,
crash-restart) remains uncovered by CI and is recorded as accepted risk in
WI-9.2.

**Not verified:** worker termination and crash-restart in WebKit. The dev app
window closed mid-probe, and the instance reached on port 9323 turned out to be
a build from the MAIN repo (cwd `/…/vmark/src-tauri`), not this worktree — so no
runtime measurement from that session is reported here. This does not gate the
verdict: the CSP question is settled by build output, and termination semantics
are specified in WI-5.3 with their own tests.

- **Description**: `grep -rn "new Worker(" src/` returns **zero hits**; there are no `?worker` imports and no Vite worker config. Every Phase 4–9 design assumes a worker. Rev 1 buried this in a risk table as "before Phase 5 commits"; by then the dialect and index designs have already committed to worker assumptions. Promoted to an explicit gating work item, per `.claude/rules/60-ai-governance.md` §7.

  - [ ] Tauri CSP (`src-tauri/tauri.conf.json`) permits the worker source; if not, the required CSP change is documented.

## Phase 5 — Worker, scheduling, deferral, and the large-file gate

Review D3-5: rev 1's WI-5.1 and WI-5.3 each bundled identity capture, cache,
lifecycle, scheduling, retry, seven guards, timers, UI and dispatch into one
unit — high cyclomatic complexity on a correctness-critical path, and each would
have breached the ~300-line file gate. Split into six.

### WI-5.1: Structure state machine (pure)
- **Acceptance criteria**:
  - [ ] A pure reducer over `StructureStatus = "ready" | "stale" | "parsing" | "unsupported-size" | "failed"` with a **complete transition table** (review D4-5: rev 1 named the states but never their transitions).
  - [ ] Every state reachable; every illegal transition rejected.
- **Required tests**:
  - **[RED]** full transition-table test — the reducer does not exist — Level 1

### WI-5.2: Revision cache with bounded retention
- **Description**: Review D2-3 — revision is part of the key, so keying without eviction leaks one MDAST/index **per edit**.
- **Acceptance criteria**:
  - [ ] **One-latest-revision retention per view identity**; bounded overall.
  - [ ] Eviction on tab close, window close, tab transfer, mode change, app shutdown.
  - [ ] Two windows / tabs / view instances never share an entry.
- **Required tests**:
  - **[RED]** N sequential edits retain exactly one entry per identity — Level 4
  - Each lifecycle event evicts — Level 4

### WI-5.3: Worker transport and ownership
- **Description**: Review D3-3 — "exactly one live request" is not implementable by dropping replies alone: a synchronous remark parse cannot be cancelled except by terminating the worker.
- **Acceptance criteria**:
  - [ ] "Live" is **defined**: queued / executing / eligible-to-commit are distinct, and the guarantee is **one committable result**, not one executing parse.
  - [ ] One shared worker with per-identity latest-wins queues; ownership model written down.
  - [ ] Crash → `failed` → next request recovers; termination leaks nothing.
- **Required tests**:
  - **[RED]** out-of-order replies: an older revision's result arriving after a newer one is **not committed** — Level 3 (real worker or real MessageChannel, not a call-count mock)
  - Keystroke storm → one committable result — Level 4

### WI-5.4: Tiered scheduling
- **Description**: Review D3-4 — **reuse `src/utils/fileSizeThresholds.ts`**, which already defines `SOURCE_MODE_DEFAULT_BYTES` (1 MiB), `WARN_BEFORE_OPEN_BYTES` (5 MiB) and `HARD_REFUSE_BYTES` (50 MiB). Rev 1 would have duplicated all three. Those are **byte** counts from filesystem metadata; the worker holds a JS string, and UTF-16 `.length` gives wrong boundaries for CJK and emoji.
- **Acceptance criteria**:
  - [ ] Thresholds imported, not redeclared.
  - [ ] Byte semantics defined: either carry source byte length in document state or compute UTF-8 size deliberately.
  - [ ] Debounce timings injectable for fake timers.
- **Required tests**:
  - **[RED]** a CJK document whose UTF-16 length is under 1 MiB but UTF-8 size is over it lands in the correct tier — fails under a naive `.length` — Level 1
  - Boundary matrix at each threshold ±1 — Level 1
  - 3 s cold-command timeout: document **byte-identical** before and after — Level 1

### WI-5.5: Exact-revision command deferral guard
- **Acceptance criteria**:
  - [ ] Seven guards (tab, view, epoch, revision, selection, read-only, IME), each with its own abandonment test.
  - [ ] Multi-range selections compared **in full**, not by count or first range.
  - [ ] No heuristic fallback path exists — asserted structurally.
- **Required tests**:
  - **[RED]** seven abandonment tests, document byte-identical each time — Level 1
  - Changing only the third of three ranges abandons — Level 1
  - Permanently cold cache mutates nothing, ever — Level 1

### WI-5.6: Structure status UI
- **Description**: Review D2-4 — rev 1 called these states "user-visible" but had no UI work item and no component test; it tested timers and i18n key presence, not whether a user sees an accessible status or whether it clears.
- **Acceptance criteria**:
