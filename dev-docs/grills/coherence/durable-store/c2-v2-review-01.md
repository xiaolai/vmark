# C2 v2 (2PC) DESIGN review (2026-07-21)

Reviewer: Codex gpt-5.6-sol (owner-delegated). Verdict: **NEEDS REVISION (7)**. The 2PC DIRECTION is confirmed correct; the mechanics need a format-1 protocol bump + atomic index publication + explicit envelope membership binding.

V2 does not pass. The logical 2PC direction is correct, but the proposed projection key and publication mechanics do not yet establish atomic visibility.

## Prior six findings

| Review-01 finding | Disposition | Assessment |
|---|---|---|
| C1 — cannot roll back a new carrier | CLOSED | Logical invisibility represents “return to absence” correctly. An uncommitted root carrier never becomes a projected revision. |
| C2 — diagnostic used as terminal compensation | CLOSED | Compensation and compensation diagnostics are removed. Abort is a lifecycle marker. |
| C3 — no atomic visibility or recovery barrier | PARTIAL | The commit marker is the right linearization concept, and abort-on-acquire is the right policy. However, revision-keyed membership, incremental application, and non-atomic rebuild publication still permit incorrect or partial visibility. |
| H1 — revert differs from restoring the base | CLOSED | No revert revision is created; projected bases remain unmoved, avoiding DAG churn and false staleness. |
| H2 — recovery contradicts always-abort | CLOSED | V2 consistently requires every recovered pending attempt to abort rather than complete forward. |
| H3 — invalid `agent.type = abort` and compatibility | PARTIAL | The provenance error is closed because markers are not transformations. The backward-compatibility half remains unresolved: an unknown format-0 commit marker makes old readers apply tentative format-0 transformations. |

## V2 attack findings

| Severity | Finding | Why |
|---|---|---|
| Critical | Revision identity cannot identify group membership. | The proposed `output.revision → attempt_id` map is neither sound nor complete. Revision IDs omit the object ID entirely ([types.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/types.rs:87)), so identical root content — or identical content and parents — can produce the same revision for different objects. For the same object, `provenance-confirmation` explicitly permits another transformation to re-emit an existing revision ([coherence-format-v0.md](/Users/joker/github/xiaolai/myprojects/vmark/dev-docs/specs/coherence-format-v0.md:394)). Merged standalone operations or multiple attempts can therefore reach the same `(object, revision)` too. A revision map can hide a legitimate non-member, expose a member under the wrong attempt, or overwrite one attempt with another. Bind membership to the exact transformation envelope — preferably a required v1 `group_attempt` field plus expected member idem recorded in the prepare. `(object, revision)` alone is still insufficient. |
| Critical | Marker existence does not prove a complete valid commit. | `committed = marker exists` exposes whatever subset of declared members happens to survive parsing. A missing, quarantined, or lost member produces a partially visible “committed” group. Worse, if the prepare is missing or rejected, manifest-derived membership treats orphaned tentative transformations as ordinary non-members and exposes them. A commit is valid only when one validated prepare, every exact declared member envelope, and one matching commit marker are present. Any missing or mismatched component must expose none. Members must self-identify as tentative so loss of the prepare fails closed. |
| Critical | The index has no atomic commit-publication path. | Current `apply_entry` first inserts into `applied`, then immediately inserts transformation revisions and edges ([index.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/index.rs:124)). A rebuild-only pre-pass does not protect the live `accept_group` path. If incremental apply instead skips a tentative member, appending the marker does not replay it; its idem is already in `applied`. `INSERT OR IGNORE` then makes the skipped state sticky until a rebuild. Additionally, `rebuild_from` clears tables and calls `apply_entry` once per entry ([index.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/index.rs:255)), publishing separate SQLite transactions, so concurrent readers can observe committed members one by one. Commit handling must publish the complete derived projection in one SQLite transaction or atomic database swap. `SCHEMA_VERSION` must also bump; otherwise a v5 index containing already-visible pending members can survive open because its applied map still matches the ledger. |
| High | Edge gating is only partly specified; resolutions are not member output. | Gating the exact transformation uniformly will gate its revision and its edges, because both are inserted in the same transformation arm ([index.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/index.rs:143)). But ratifications and waivers are independent ledger entries and are inserted independently ([index.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/index.rs:191)). The same issue applies to check results and other records keyed by `(txf, input)`. V2 alternately says resolutions are unaffected and that they share the member gate. Specify that every edge-scoped projection record remains invisible while its referenced edge is tentative, then activates in the same atomic publication as the edge. |
| High | Terminal-state and recovery-barrier rules are incomplete. | Abort-on-acquire is logically correct and idempotent if the abort idem derives from the attempt. Option A’s reconcile-before-settle ordering is also correct: reconcile first hides pending members, then abort records the decision. But `commit` and `abort` can coexist after a branch merge; V2’s “commit exists” rule exposes the attempt while another passage says aborted members never appear. This must fail closed as a terminal-state conflict, not let commit win. Settlement must consider only validated attempts, append aborts under the already-held lock without recursively entering `with_write_lock`, and block the caller if every pending attempt cannot be durably settled. Once the Critical publication issues are fixed, no pending member is observable live during this sequence. |
| High | A format bump prevents over-exposure only under a stricter migration contract. | If every v2 prepare, member transformation, and terminal marker is format 1, the current format-0 reader skips those records, so it does not over-expose tentative members ([ledger.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/ledger.rs:367)). If only the unknown marker is bumped while members remain format 0, the old reader definitely over-exposes them. Even a global bump is not fully safe today: future-format records are skipped while the reader continues with truncated history ([ledger.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/ledger.rs:246)), allowing an old writer to mutate from a false projection. Make this format 1, require fail-closed workspace mutation whenever `future_format > 0`, and document that old binaries may see v1 history as absent. A separate commit marker is better than a field on prepare: an append-only prepare cannot later transition to committed. Use the marker plus explicit group membership on each transformation. |
| High | Retry identity works, but “commits fresh” conflicts with the current format invariant. | With correct tentative gating, bases remain unmoved, the same candidates produce the same `group_id`, and `attempt_id_for(..., supersedes=aborted_attempt)` produces a fresh attempt; attempt-folded member idems also prevent reuse. That part is sound. But the fresh attempt emits the same content-addressed revision IDs as the aborted attempt, while the current spec says any non-confirmation transformation re-emitting an existing revision is malformed ([coherence-format-v0.md](/Users/joker/github/xiaolai/myprojects/vmark/dev-docs/specs/coherence-format-v0.md:396)). Format 1 must state explicitly that an output from a never-committed/aborted attempt is not a projected “existing revision,” and a later superseding attempt may emit that revision under a new member envelope. Also qualify “same bases”: it holds only absent external/raw-git changes between attempts. |

`INSERT OR IGNORE` on `revisions` is safe only after these corrections: a legitimate non-member may insert the revision first, and a later committed member may ignore that duplicate revision row while still inserting its own entry-addressed edges. It is unsafe with the proposed incremental skip because the earlier `applied` row prevents materialization.

Concrete format recommendation: format 1; separate `group-commit` and `group-abort` marker kinds; a required group-attempt/member-idem binding on each tentative transformation; commit validity requiring the complete exact manifest; commit/abort coexistence failing closed; one-transaction projection publication; schema-version bump.

VERDICT: c2-v2: NEEDS REVISION (7)
