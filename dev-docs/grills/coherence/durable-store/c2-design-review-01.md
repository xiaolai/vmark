# C2 abort-recovery DESIGN review (2026-07-21)

Reviewer: Codex gpt-5.6-sol (owner-delegated). Verdict: **NEEDS REVISION (6: 3 Critical + 3 High)** — physical-revert compensation is the wrong mechanism; use logical tentative-visibility (2PC).

| Severity | Finding | Why |
|---|---|---|
| Critical | Physical compensation cannot roll back a newly created object. | Group members explicitly permit `(no parent, object absent)` ([accept_group.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/accept_group.rs:130)), and Extract-Canon commits its brand-new carrier first ([extract_canon.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/extract_canon.rs:43)). Its snapshot has no base revision or content. A transformation always creates/revives a revision; there is no durable transformation representing “return to absence.” This is the most likely partial-crash window, not an edge case. Use logical tentative/void semantics or add a durable tombstone before physical rollback can satisfy the directive. |
| Critical | A conflict diagnostic is not compensation, yet the design makes it terminal. | The proposed ordering appends “compensation (or diagnostic)” and then `group-abort` ([design](/Users/joker/github/xiaolai/myprojects/vmark/dev-docs/grills/coherence/durable-store/c2-abort-recovery-design.md:65)). That marks the attempt dead while a committed member or its descendant remains live. If the diagnostic shares the compensation idem, it also permanently poisons later recovery: idem-present will be mistaken for a completed revert. `heads == {member_revision}` is a sufficient guard for safely appending a child under the reconciled write lock, but it is not a complete rollback-state test. A mismatch may be a descendant, sibling/multi-head, or an independent external revert. A cooperating same-group retry cannot interleave because of the lock; external history remains ambiguous. Conflict needs a separate blocking lifecycle state, and `group-abort` must be appended only after every committed member has verifiable compensation — never after a diagnostic. |
| Critical | The protocol cannot provide its stated atomic visibility, and there is no recovery barrier. | Transformations immediately enter the revision DAG/head projection ([index.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/index.rs:143)); each member and compensation is appended separately. Therefore crashes between members or compensations necessarily leave a durable, visible mixture, contradicting the invariant in the design ([design](/Users/joker/github/xiaolai/myprojects/vmark/dev-docs/grills/coherence/durable-store/c2-abort-recovery-design.md:20)). Lock acquisition only reconciles the index ([state.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/state.rs:280)); it does not recover pending groups. After a crash, an ordinary cooperating writer can extend a partial member before `recover_group` is called, making rollback conflict. Prefer tentative group members excluded from live projection until a durable `group-commit` marker; abort then exposes none. At minimum, enumerate and settle pending groups before any projection or mutation. |
| High | A revert revision is not equivalent to restoring the base revision. | For `B → M → R(content=B)`, `R` is a new head. Existing downstream edges pinned to `B` become version-stale because `B` is an ancestor of `R`; edges pinned to `M` also become stale; edges produced by `M` are retired by downstream-head liveness ([project.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/project.rs:124)). A retry parented on `R` also has different member revisions and ungrouped idems, so `group_id` changes and it cannot actually `supersede` the aborted attempt as claimed ([accept_group.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/accept_group.rs:247)). Repeated aborts accumulate `B→M→R→M→R` chains and false staleness. O(ledger) reconciliation faithfully recreates this churn; it does not repair it. Physical revert has smaller code blast radius but materially worse semantics than logical visibility/voiding. |
| High | The design contradicts the owner’s recovery policy. | It says a partial “always rolls back, never completes-forward” ([design](/Users/joker/github/xiaolai/myprojects/vmark/dev-docs/grills/coherence/durable-store/c2-abort-recovery-design.md:3)), but the implementation section changes only the revalidation-failure path and retains completion when revalidation succeeds ([design](/Users/joker/github/xiaolai/myprojects/vmark/dev-docs/grills/coherence/durable-store/c2-abort-recovery-design.md:93)). Both current recovery paths explicitly commit missing members after successful revalidation ([accept_group.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/accept_group.rs:303), [accept_group.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/accept_group.rs:473)). The design must choose one state machine. Under the stated directive, every recovered partial must abort, including an otherwise revalidatable one. |
| High | `agent.type = "abort"` is the wrong provenance contract and is not backward-compatible as proposed. | Agent types are specified in §5.4.1, not §8; §8 defines confidence. The current closed set is `human/model/external/git` ([spec](/Users/joker/github/xiaolai/myprojects/vmark/dev-docs/specs/coherence-format-v0.md:315), [types.rs](/Users/joker/github/xiaolai/myprojects/vmark/src-tauri/src/coherence/types.rs:123)). `abort` describes an action, not an agent. Adding it under format v0 makes older readers reject/quarantine the known transformation, reconstructing the original member as live. Do not reuse `git` or `external`: neither truthfully describes an internally generated compensation. If physical compensation survives the redesign, add `agent.type = "system"` with `intent.kind = "group-abort-compensation"` and an explicit format/spec compatibility decision. Logical group visibility would avoid needing a compensation agent entirely. |

c2-design: NEEDS REVISION (6)
